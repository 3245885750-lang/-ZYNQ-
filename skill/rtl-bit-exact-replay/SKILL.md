# 逐位回放验证（RTL Bit-Exact Replay）

## 适用场景

改了 RTL 里的**输出级逻辑**（门控、限速、计数器、状态机），但不想每次上板或跑
完整仿真来确认行为。典型场景是「参数从 A 调到 B，稳态会不会被带坏」这种 A/B 问题。

不适用于：DSP 数据通路（FFT、求逆、扫角）的行为验证——那需要真实数据激励和
testbench，回放模型只覆盖控制逻辑。

## 使用方法

1. **把 RTL 逻辑翻译成 Python**，整数语义必须完全一致：
   - 寄存器位宽（例如 `reg [3:0] gate_cnt` 就是 `& 15`）；
   - 饱和 / 回绕（是 `min(x+1, 7)` 还是 4 bit 自然回绕，必须和 RTL 一致）；
   - 组合逻辑的先后顺序（`accept_any` 与 `sig_ok` 的与关系）。
2. **跑 A/B**：同一份输入 CSV，分别用旧参数和新参数回放，逐帧比较。
3. **参数一致性检查**：`python sim/model/param_check.py`，从 RTL 文本里抠
   `parameter integer` 与模型常量逐项比对，防止「RTL 改了、脚本忘了改」。
4. 只有 A/B 差异全部落在预期区间（例如只在记录间隙或声源启动段），才进综合。

仓库内参考实现：

```
sim/model/sim_clap_smooth.py   # 输出级三变体 A/B/C 逐帧回放
sim/model/sim_big.py           # 大角度转动与静态一致性
sim/model/param_check.py       # RTL 参数 vs 模型常量
sim/model/sim_gate.py          # 门控单独回放
sim/model/sim_slew.py          # 限速单独回放
```

## 已验证效果

在「拍手后角度漂移」的修复中，用回放模型先确认方案、再改 RTL：

| 数据 | A（旧）vs C（新）差异帧 | 说明 |
|---|---|---|
| `static_v4.csv` | 0 / 1144 | 静止声源完全不受影响 |
| `circle_v5.csv` | 28 / 7178（0.4%） | 差异在记录间隙 |
| `circle_fast.csv` | 19 / 1991 | 同上 |
| `circle_slow2.csv` | 52 / 6666 | 同上 |

回放还抓出了一个真实缺陷：禁用强制放行后，4 bit 计数器会回绕到 0，
`(cnt+1) >= 8` 永远不成立，强制放行永久失效。这个缺陷在 RTL 里只占一行，
不建模基本发现不了。

## 失效条件

- 模型位宽与 RTL 不一致时，结论无效。典型错误：模型用 Python 任意精度整数，
  RTL 是 4 bit —— 回绕行为完全不同。
- 回放只验证控制逻辑，不验证数值精度；如果改动涉及定点位宽或舍入，仍需仿真。
- CSV 输入本身是板上采到的角度序列，不含原始音频；不能用来推断「算法为什么错」。
