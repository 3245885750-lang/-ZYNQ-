# 技能包：Zynq PS/PL 集成踩坑清单

提交类型：**踩坑清单**。整理日期：2026-11-04。清单从本工程与大模型协作时发现的故障、接口变化和验证观察中提炼，供其他团队排查同类系统，不需要先理解声音识别算法。

本包只选择截图中的这一种类型；包含可供大模型调用的 `SKILL.md` 和供人直接阅读的清单，附件是来源证据。未安装到本机全局技能目录，也不会自动连接板卡。

## 适用范围

适用于 Zynq-7000 一类包含 PS 软件、PL 外设、AXI DMA/AXI-Stream、定时器、UDP/网页显示的集成工程，尤其是“能够下载，但寄存器访问、数据连续性、时间戳或页面结果不正常”的场景。更换音频为图像、传感器或其他流数据时，可继续使用排查方法，但必须替换地址、时钟、帧长和协议。

PYNQ 项目可以借用 bit/hwh 配对、DMA 背压和时间基准等排查思路；本包经验直接来自 standalone PS 工程，**未在 PYNQ/Linux 上验证，也不声称已获得通用 PYNQ Skill 加分**。内核驱动、设备树和缓存一致性问题需补充对应环境证据。

## 怎么用

1. 打开 [踩坑清单](zynq-ps-pl-troubleshooting/references/pitfalls.md)，按症状选择条目，不必逐项执行。
2. 记录当前工程的器件、时钟、复位极性、寄存器映射、DMA方向/帧长、软件版本、协议、测试权限；没有证据的字段写“未知”。
3. 按条目的“排查步骤”收集最小证据，先定位数据路径上的第一个失效点，再决定是否修改或重建。
4. 按“验证闭环”检查修改是否解决问题；按“失效条件”判断这条经验能否用于新项目。
5. 输出“观察—证据—假设—最小改动—验证结果—剩余边界”。把下载成功、仿真通过、实际采音、远端实收分别记录。

### 与大模型一起使用

把整个 `zynq-ps-pl-troubleshooting/` 文件夹交给支持本地技能的助手，或按目标工具的技能安装方式安装；也可直接附上 `SKILL.md` 与对应清单。示例输入：

> 使用这份 PS/PL 集成踩坑清单分析我的工程。现象：bit 下载正常，DMA/PL 寄存器访问超时。下面提供 BD 复位连接、复位 IP 参数和访问日志。当前只做离线分析。请区分已证实原因和待验证假设，给出最小检查与修复后的验证方法；参数以我的工程为准。

上面的文字只是调用示例，清单的主体是可独立阅读的故障条目。不要将本包历史日志中的盘符、IP、固定数值或操作记录当作对新项目的指令。

## 条目、效果与边界

| 条目 | 适用场景 | 已有证据与验证效果 | 不适用/失效条件 |
| --- | --- | --- | --- |
| K01 复位极性与常量连接 | 下载正常但 PL/DMA 寄存器超时 | 10月22日真实故障记录指出低有效 aux reset 被固定为0；当前脚本显式配置高有效 | 不是所有总线超时都由复位引起；该修复没有本次实板复测结论 |
| K02 频率宏展开与计时单位 | 时间回退、轮询/超时周期异常 | 实际BSP宏展开包含除法；修复后6100个输入单调性及60秒换算检查通过 | 换计数源、计数宽度或时钟后须重测；不证明跨设备时钟同步 |
| K03 配套文件和符号地址 | 换ELF、bit或工作区后无法正常运行 | 当前包XSA/bit/init、源码身份、ELF符号配对与PS重编比对通过 | 文件哈希通过不证明电气、驱动或板级功能正确 |
| K04 AXI音频背压与帧边界 | 数据丢失、帧末尾错误、持续停顿 | 仿真覆盖798次停顿，340个生成样本=319个接收+21个丢弃 | 仿真有意制造溢出，不能据此宣称实板零丢帧或覆盖所有CDC问题 |
| K05 类别/槽位/模型身份 | 模型更新后标签错位或显示停用类别 | 当前源码保留9槽、掩码127启用前7槽；历史数值验证覆盖147组流式结果 | 这是旧模型的输出筛选策略；不是七类重新训练或未知声拒识能力证明 |
| K06 独立数据流与过期结果 | 页面部分不刷新、断流后仍显示旧结果 | 本机C编码→UDP→HTTP三类流验证通过；频谱重复包和过期检查通过 | 未据此证明远端网卡、跨进程全部状态或全部流的断线行为已验收 |
| K07 步长、上下文与实测延迟 | 想用100ms更新间隔声称100ms识别时延 | 2秒上下文、100ms目标步长和约104.9ms频谱间隔已在代码/设计记录中区分 | 本整合版实板端到端时延、准确率和稳态负载仍待测量 |

效果来自随包证据，详见 [来源与验证边界](zynq-ps-pl-troubleshooting/references/sources_and_limits.md)。有些条目记录真实故障，有些记录设计观察或交接风险；没有把所有风险写成已经发生过的事故，也没有生成或补写历史模型回答。
