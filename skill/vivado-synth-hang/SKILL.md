# Vivado 综合/实现卡死排查

## 适用场景

Vivado 综合或实现长时间没有输出、进度条不动、机器内存被吃满甚至整机卡顿。
需要在不重启工具、不重跑工程的前提下判断「是在算，还是已经死了」。

注意：不要在有其他重负载任务时启动综合/实现，也不要在远端会话里同时开多个
Vivado 实例。本项目的一条硬规则是——**综合/实现由工程负责人在本机手动启动**，
AI 助手只做只读检查。

## 使用方法

```powershell
# 只读检查：进程、CPU、内存、日志时间戳、运行标记
powershell -ExecutionPolicy Bypass -File build\check_vivado.ps1
```

脚本检查以下信号：

| 信号 | 含义 |
|---|---|
| `vivado.exe` 进程数与 CPU 时间 | CPU 时间在涨 = 还在算 |
| 内存占用 | 接近物理内存上限 = 即将换页，会假死 |
| `runme.log` 最后修改时间 | 超过 10 分钟不变 = 可能卡住 |
| `*.rst` / `*.dcp` 临时文件 | 存在 = 当前 run 未完成 |
| 日志末尾关键字 | `Finished` / `ERROR` / `CRITICAL WARNING` |

判断顺序：

1. **CPU 时间在涨** → 正常，等待；
2. **CPU 时间为 0 且日志不动** → 可能死锁，导出 `vivado.log` 后重启 run；
3. **内存接近上限** → 减小并行度（`-jobs 1`）、关闭其他程序，再重跑；
4. **机器整体卡顿** → 不是 Vivado 单方面问题，先停掉其他重负载进程。

## 已验证效果

`build/check_vivado.ps1` 在本项目中用于区分「综合真的在跑」与「日志 0 字节、
实际已退出」两种情况。曾遇到 `runme.log` 大小为 0 但进程仍在的情况，
最终确认是 run 目录残留，重置 run 后正常。

## 失效条件

- 脚本只读，不会修复问题；它回答「是否还在算」，不回答「为什么慢」。
- 在 Linux 或无 PowerShell 环境下需要改写为 `ps` / `top` 版本。
- 如果 Vivado 是通过远程桌面启动的，进程可能属于另一个会话，需管理员权限查看。
