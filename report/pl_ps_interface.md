## 0. 一句话

PS 通过 **AXI4-Lite 从机**控制/读取两路测向结果：
- **DOA**（`0x08`）—— MVDR **8 bin 宽带精测**，**47.7 Hz 持续刷新**（每 21ms 一个新值，不是一次性的），
  全 360°、有符号度。已做单帧离群剔除（GATE）与显示限速（≤8°/帧）。
- **DAS_DOA**（`0x20`）—— 时域延时求和**快速粗测**，~21ms/次，分数延时 1° 步长、无偏（~±2-3°）。
- **频谱流**（`fft_axis_*`）—— 8 路 FFT 频谱，经 **AXI DMA → DDR** 送 PS，再转发 PC 做**可视化**（实时频谱 / 8 方位波束谱 / 语谱图）。**识别已改在 PS 做，吃的是波束音频那一路**。见 §8。

PL 内部的 I2S → FFT → 协方差 → 求逆 → 扫角（精测）+ 延时求和（粗测）全链路已经自己跑通。B 要管的是把频谱流经 DMA 搬进 DDR 再送 PC。

## 3. 寄存器映射（字节地址，每个 32bit）

基地址由 AXI 互连分配（PS 的 M_AXI_GP0），下表的偏移从基地址算起。

| 字节地址 | 字地址 | 名称 | 属性 | 说明 |
|---|---|---|---|---|
| 0x00 | 0 | CTRL | W | bit0 = START（**自清**，写 1 启动一次测向）；bit1 = SOFT_RST（自清，复位内部链路） |
| 0x04 | 1 | STATUS | R | bit0 = BUSY；bit1 = DONE（**粘滞**，写完 START 才清） |
| 0x08 | 2 | DOA | R | 估计角度，**有符号度** −180..+180，32bit 符号扩展。含运动超前补偿（`PRED_EN=1`，连续 4 帧同向匀速才生效；静止声源与未补偿值相同） |
| 0x0C | 3 | S_MIN | R | 本次最小 s 值（Q16.16 原始值，越小越可信，调试用） |
| 0x10 | 4 | SHIFT_USED | R | 协方差归一化右移量（调试用） |
| 0x14 | 5 | SNAP_CNT | R | 已累积快拍数 0..K |
| 0x18 | 6 | BIN_LIST | R | `{16'd0, BIN0, BIN1}`，编译期参数（当前 5 / 10） |
| 0x1C | 7 | VERSION | R | `0x4D564452` = 字符 "MVDR" |
| 0x20 | 8 | DAS_DOA | R | DAS 快速粗 DOA，**有符号度** −180..+180（分数延时 1° 步长，~21ms 更新，宽带任意声音） |
| 0x24 | 9 | DAS_STATUS | R | bit0 = 有无信号（DAS 束功率门限，1 = 有信号） |
| 0x28 | 10 | BIN_LIST2 | R | `{BIN2, BIN3}`（当前 15 / 20） |
| 0x2C | 11 | BIN_LIST3 | R | `{BIN4, BIN5}`（当前 25 / 31） |
| 0x30 | 12 | BIN_LIST4 | R | `{BIN6, BIN7}`（当前 37 / 43） |
| 0x34 | 13 | PWR | R | **MVDR 总能量（8 bin 对角线迹的 EMA）**：无信号≈0，判"有没有声"用这个 |

> 读写属性：R = 只读，W = 只写（读回 0）。
> 读 CTRL 返回 0，写只读寄存器无副作用。

### 两路结果怎么用（粗 + 精）

- **DAS_DOA（0x20）**：`~21ms` 刷一次，宽带任意声音都能粗定位（分数延时 1° 步长，~±2-3°，无原整数延时偏置）。
  适合**实时跟踪**声源大致方向、快速响应。
- **DOA（0x08）**：MVDR 8 bin 宽带精测，**47.7Hz 持续刷新**，连续声源 ±1~2°。
  已做离群剔除（GATE）+ 显示限速（正常 ≤8°/帧），所以轨迹是平滑的，可以放心画图。
- 两者都读，即可「先粗锁定、再精确认」。DAS 不需要 START/轮询 DONE，随时读都是最新值；
  判断有无信号读 `DAS_STATUS.bit0`。

## 4. 典型读取流程（`AUTO_RUN=1`，上电自跑）

交付给 B 的 `radar_pl_top_bd` 里 **`AUTO_RUN=1`、`K=2`**：上电就开始连续测向，
**每 21ms（47.7Hz）更新一次 DOA，PS 不需要写 START**，直接按需要的节奏轮询读即可：

```
1. 读 VERSION（0x1C）应为 0x4D564452           // 自检连接
2. 读 PWR（0x34）> 门限 才算"有信号"           // 无信号时 DOA 无意义
3. 读 DOA（0x08），int32_t 直接就是 -180..+180  // 随时读都是最新值
```

> 如果需要"测一次停一次"，可以让 A 把 `AUTO_RUN` 改回 0，那时才用
> `写 CTRL=0x1 → 轮询 STATUS.bit1 → 读 DOA` 的流程。

### C 伪代码（Linux 下 mmap 到寄存器后）

```c
#define REG_CTRL     0x00   // 只写
#define REG_STATUS   0x04   // 只读
#define REG_DOA      0x08   // 只读
#define REG_VERSION  0x1C   // 只读

uint32_t rd(uint32_t off) { return *(volatile uint32_t*)(base + off); }
void     wr(uint32_t off, uint32_t v) { *(volatile uint32_t*)(base + off) = v; }

// 上电自检：读版本号应为 0x4D564452
if (rd(REG_VERSION) != 0x4D564452) { /* 连接/地址错 */ }

// 启动一次测向
wr(REG_CTRL, 0x1);

// 等完成（轮询 DONE 位）
while (!(rd(REG_STATUS) & 0x2)) ;   // 等 bit1 DONE

// 读结果（有符号度，int32_t 直接就是 −180..+180）
int32_t doa = (int32_t)rd(REG_DOA);
```

## 5. 结果含义

- **DOA**：有符号度。当前圆周阵列（UCA）测向范围 **−180..+180**、**无镜像模糊**（2026-10-16 起）。
  直线阵列测试阶段的范围是 −90..+90（有左右镜像），已弃用；接口不变，只是数值范围变了。
- **S_MIN**：MVDR 空间谱的最小值（Q16.16，越小代表零陷越深、方向越可信）。纯噪声时会比较平、数值偏大，可用来判断「当前到底有没有一个明确声源」。
- **SNAP_CNT**：实时快拍计数，可用来观测进度（0 → K 走完即出结果）。

## 6. 已知限制（B 联调时注意）

1. **MVDR 覆盖的是 8 个离散 bin，不是连续频带**：
   - 目标 bin = 5/10/15/20/25/31/37/43 → 476.9 / 953.7 / 1430.5 / 1907.4 / 2384.3 / 2956.6 / 3528.8 / 4100.8 Hz。
   - FFT 不加窗，单音必须落在某个 bin ±0.5 bin（±48 Hz）内才收得到能量：1kHz 相对满幅 −3.8 dB，
     2kHz −30 dB、4kHz −25 dB（实测"必须贴着麦克风"就是这个原因）。
   - **宽带声（说话/拍手/音乐）不受影响**，因为它同时激励多个 bin。
   - DAS 粗测（`0x20`）是时域宽带，任何声音都能粗定位。
2. **bin 号编译期固定**：运行期改不了（要改得重新综合并重新生成 steering `.mem`）。
3. **单时钟域**：如果 PS 走独立时钟（比如 AXI 用 100MHz），需要加 CDC。
4. **DONE 粘滞**：完成后 DONE 一直保持 1，直到下次写 START 才清。
5. **无中断**：只支持轮询 STATUS，没有中断线。要中断让 A 加。

## 8. 频谱输出 AXI4-Stream（给 DMA，供 PC 可视化）

> **2026-10-22 更新**：识别已改在 PS 做（吃波束音频），频谱流现在的用途是**给 PC 画图**：
> 实时频谱、8 个方位的波束谱、语谱图。完整方案见根目录 `频谱显示.md`。

**端口已引出**：`radar_pl_top_bd.v` 已有 `fft_axis_tdata/tvalid/tlast`（输出）和 `fft_axis_tready`（输入），B 直接接 DMA 即可。

> ⚠️ `fft_axis_tready` **与内部 MVDR 共用**（同一路流、同一握手）：DMA 停 → MVDR 也暂停，不丢数据。
> 需要两路独立背压时，在 BD 里加 AXI4-Stream Broadcaster。

| 信号 | 方向 | 位宽 | 说明 |
|---|---|---|---|
| `fft_axis_tdata` | PL→DMA | 64 | `{imag[31:0], real[31:0]}`，real 在低 32 位 |
| `fft_axis_tvalid` | PL→DMA | 1 | 数据有效 |
| `fft_axis_tlast` | PL→DMA | 1 | 每路第 512 点（帧末）拉高 |
| `fft_axis_tready` | DMA→PL | 1 | 背压（现在 PL 内暂拉 1，BD 阶段接 DMA 的 `S_AXIS_S2MM_tready`） |

### 数据格式与流结构

- **一个字 64bit**：`{imag[31:0], real[31:0]}`。有效精度 24bit，real 取 `[31:8]`、imag 取 `[63:40]`。
- **8 路 × 512 bin 分时复用**：ch0 的 bin0..511 → ch1 的 bin0..511 → … → ch7。每路最后一点 `tlast=1`。
- **一轮 = 4096 字（32KB）**：数满 8 次 `tlast` 就是一轮完整的 8 路频谱（同一时刻 8 个麦克风的谱）。
- 采样率 48.828kHz、512 点 FFT → **bin 分辨率 95.4Hz**，bin `k` 对应 `k × 95.4Hz`。
- **PC 可视化需要全部 8 路的复数谱**（8 方位波束谱要把 8 路一起算），不能只转 ch0。

### 时序 / 吞吐

- 流时钟 50MHz，1 拍 1 字（64bit）。
- 一轮 4096 字突发 ~82us，每 ~10.49ms 来一轮（FFT 一帧采样时间），平均 **~3.1MB/s**。
- 下游（DMA/PS）只要平均吞吐 ≥3.1MB/s 就不会丢；突发间有空档，异步 FIFO 负责抹平 50→100MHz 时钟差。

### B 要做的（PS 侧）

1. BD 里例化 AXI DMA，`S_AXIS_S2MM` 接本流（中间加一个异步 FIFO 跨 50→FCLK_CLK0）。
2. PS 初始化 DMA（S2MM 通道），配好接收缓冲区（≥ 一轮 32KB，建议 N 个缓冲轮转）。
3. 收到数据后打包（每轮 8×512×64bit，或只取 ch0 的 512×64bit）经网口送 PC。
4. **PS 侧用这 8 路复数谱算 8 方位波束谱**（公式与角度映射见 `频谱显示.md` 第三、九节），
   连同波束音频的识别结果一起打包发 PC；PC 只负责画。

> 已完成（2026-10-22）：A 已把 4 个端口引到 `radar_pl_top_bd.v` 顶层，`fft_axis_tready` 直接接 DMA 的 `S_AXIS_S2MM_tready`。

## 附：AXI4-Lite 时序约定（供 B 写驱动参考）

标准 AXI4-Lite，无特殊：
- **读**：`arready` 空闲时为 1；收到 AR 后下一拍 `rvalid=1` 且给出 `rdata`（单拍读）。
- **写**：`awready`/`wready` 空闲时都为 1；AW 和 W 都收到后下一拍发 `wr_en` 并回 `bvalid`。
- 地址位用字节地址的 `[5:2]`（16 个 32bit 寄存器空间），高位由互连决定。
