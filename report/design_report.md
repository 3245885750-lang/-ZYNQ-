## 一、设计概述

### 1.1 设计目的

本项目实现一套完整的声学阵列处理系统：用 8 个 MEMS 麦克风组成均匀圆周阵列，
在 FPGA 上实时估计声源方位（1° 分辨率、全 360° 无镜像模糊），按估计角度做波束
形成得到增强后的单路音频，并由处理器对音频做九类声源识别，结果通过以太网送到
上位机显示。

#### 1.1.1 选题背景

声源定位在会议拾音、工业异响诊断、安防异常声检测中有明确需求。传统做法有两种
极端：纯 PC 软件方案算力足但延迟高、功耗大，难以长期在线；纯 MCU 方案实时性好
但算不动 8 路的协方差求逆与全角度扫描。ZYNQ-7020 的 PL 侧适合做确定性、高吞吐
的阵列前端，PS 侧适合跑迭代频繁的识别模型，正好覆盖「硬实时测向 + 柔性识别」
这两类负载。

选择圆周阵列而不是直线阵，是因为比赛场景要求全 360° 无镜像模糊；选择 8 阵元
是在角度分辨率（阵列孔径决定）与资源（协方差规模随阵元数平方增长）之间折中。
在此基础上，连续声源（说话、音乐）用宽带 MVDR 已经可以稳定到 ±1–2°，但拍手
这类约 1 ms 的瞬态，在 10.7 ms 的 FFT 窗里混入了大量到达前噪声与反射，单帧
空间谱方差大、角度会跳——这是本项目在联调阶段暴露出的主要问题，也是第三章
3.8 节引入独立的瞬态 TDOA 支路的原因。

### 1.2 应用领域

- 会议与视频会议拾音：自动指向发言人，抑制环境噪声；
- 工业设备异响定位：判断异常噪声来自哪台设备、哪个方位；
- 安防异常声检测：拍手、鸣笛、玻璃破碎等突发声的方向与类型；
- 教学演示：阵列信号处理与软硬协同设计的完整案例。

### 1.3 系统主要特点

1. **全 360° 无镜像模糊**：采用圆周阵列而非直线阵，避免直线阵固有的左右模糊。
2. **宽带非相干融合**：8 个频点（476.9–4100.8 Hz）的空间谱相加，压掉单频栅瓣。
3. **硬实时**：PL 单 50 MHz 时钟域内完成采集、FFT、协方差、求逆与扫角，
   DOA 每 21 ms 更新一次，不依赖 CPU。
4. **软硬协同**：PL 做确定性硬实时，PS 做柔性识别，PC 只负责绘图。
5. **双支路测向**：连续声源用 8 bin MVDR，拍手等瞬态用脉冲前沿 TDOA，
   由状态位自动切换，互不干扰。

### 1.5 主要创新点

1. **8 频点宽带非相干 MVDR + 自适应记忆**：单频 MVDR 的栅瓣随频率移动，
   纯音下 DOA 在正确角附近跳动；8 个频点融合后栅瓣互相抵消。协方差用遗忘因子
   滑动（S=7），检测到信号消失时切 S=3，拍手拖尾从约 2.5 s 缩短到约 0.3 s，
   稳态精度不受影响。
2. **资源受限下的算子时分复用**：8 倍 MVDR 算力若全部展开会超出 XC7Z020。
   `cov_to_q16` 只例化 1 份并前置 8:1 选择器，`mat_inv_8x8` 用序列状态机复用 8 次，
   基线版 LUT 54.8%；加入瞬态 TDOA 支路后为 66.5%，仍在 XC7Z020 余量内。
3. **PL / PS / PC 三段异构分工**：PL 硬实时、PS 柔性分类与组包、PC 可视化与声纹推理；
   AXI4-Stream 传波束音频（97.7 kB/s），千兆网 UDP 传 JSON v3 结果与 16 kHz 音频包。
4. **瞬态专用 TDOA 支路与连续 MVDR 并存**：连续声源走 8 bin MVDR，拍手等瞬态
   走脉冲前沿 TDOA，由 `0x54` 的状态位决定显示哪一路。两条支路共享同一套 I2S
   前端，TDOA 只在触发后的 500 ms 内接管输出，互不干扰。

## 二、系统方案

### 2.1 总体架构

```
┌────────────────── PL（50 MHz，硬实时） ──────────────────┐   ┌──── PS（Cortex-A9） ────┐   ┌── PC ──┐
│ I2S×8 → FFT512 → bin抽取 → 协方差 → 求逆                 │   │ lwIP / UDP 发送         │   │ 接收    │
│              → MVDR 扫角 → GATE/SLEW → DOA（0x08）        │──▶│ MLP 九分类              │──▶│ 解析    │
│ I2S×8 → 差分 → 双包络 → 触发 → 环形缓存 → 首达沿          │   │ 组包（JSON）            │   │ 显示    │
│       → 加权最小二乘 → 相干门控 → TDOA（0x50/0x54）       │   │ 显示选择（保持 500 ms） │   │         │
│              → 时域 DAS → 波束音频 ───────────────────────┼──▶│                         │   │         │
└───────────────────────────────────────────────────────────┘   └─────────────────────────┘   └────────┘
        AXI4-Lite（寄存器轮询）        AXI4-Stream（音频/频谱）        千兆以太网 UDP 9000（JSON + 音频包）
```

### 2.2 关键设计决策

1. **为什么用圆周阵列**：直线阵在 ±90° 附近存在左右镜像模糊，且端射方向分辨率
   急剧下降。圆周阵列全 360° 无模糊，代价是导向矢量随角度非线性、需要 361 点
   全角度扫描。
2. **为什么 8 个频点非相干融合**：单频空间谱的栅瓣位置由 kR 决定，是频率相关的；
   不同频率的栅瓣落在不同角度，相加后互相抵消，而主瓣在所有频率都对准声源。
3. **为什么识别放 PS**：PL 资源已用 66.5%（基线 54.8%），且识别算法迭代频繁；放 PS 改算法
   不需要重新综合，符合「硬实时在 PL、柔性在 PS」的分工。
4. **为什么用网线回传而不是板载显示**：帧缓冲放不进 BRAM，视频时序开发量大，
   且 PC 端绘图更灵活。
5. **两套 RTL 的取舍**：交付 bitstream 使用与 PS 固件配套的基线 IP；
   `src/pl/rtl/` 保留输出端优化的开发版，便于复现与继续演进（详见 README 第 3 节）。

### 2.3 软硬件划分依据与接口设计

#### 2.3.1 划分依据

划分原则只有一条：**确定性、高吞吐、与采样时钟强相关的放在 PL；依赖操作系统、
需要频繁迭代、结果允许几十毫秒延迟的放在 PS。**

| 任务 | 位置 | 选择理由 | 代价 |
|---|---|---|---|
| I2S 采集、去直流、FFT512 | PL | 与 48.828 kHz 采样时钟同域，抖动要求 1 个采样以内 | 占用 BRAM 与 FFT IP |
| 8×8 协方差、求逆、361 点扫角 | PL | 每 21 ms 必须完成，CPU 上无法保证实时性 | 算子必须时分复用才放得下 |
| 瞬态检测、首达沿、TDOA | PL | 首达沿分辨率约 1 个采样（20 ns），跨时钟读取会丢精度 | 需要额外环形缓存 |
| 门控/限速/显示选择 | PL | 与 DOA 同拍产生，放 PS 会多一次 AXI 往返 | 参数改动要重新综合 |
| MLP 九分类 | PS | 模型与特征工程迭代频繁，重新综合代价高 | 结果更新步进 100 ms 量级 |
| 组包、UDP、网页、声纹 | PS / PC | 网络栈与可视化属于通用软件；CAM++ 声纹推理放 PC，不占板端算力 | 依赖 lwIP 与 PC 环境 |

#### 2.3.2 AXI4-Lite 接口

PS 只通过一组 32 bit 寄存器访问 PL，基地址 `0x43C00000`。完整位定义见
`report/pl_ps_interface.md`，这里只列契约级摘要：

| 偏移 | 名称 | 属性 | 契约 |
|---|---|---|---|
| `0x00` | CTRL | W | bit0 START（自清）；bit1 SOFT_RST |
| `0x04` | STATUS | R | bit0 BUSY；bit1 DONE（粘滞） |
| `0x08` | DOA | R | 连续声源 MVDR 角度，有符号度 |
| `0x1C` | VERSION | R | `0x4D564452`，联调自检 |
| `0x20` | DAS_DOA | R | 时域 DAS 粗测角度 |
| `0x34` | PWR | R | 8 bin 总能量，判「有没有声」 |
| `0x50` | TDOA_DOA | R | 瞬态 TDOA 角度，有符号 9 bit（RTL 已扩展为 32 bit） |
| `0x54` | TDOA_STATUS | R | bit0 保持中；bit1 上次低置信；bit2 已有结果 |

契约要点：

- `0x50` 在 RTL 内已用 `{{23{tdoa_doa[8]}}, tdoa_doa}` 做 32 bit 符号扩展；
  若换成本仓库以外的实现、只拿到裸 9 bit，按 `(int32_t)(v << 23) >> 23`
  处理（对已扩展的值是幂等的）；
- `0x54` bit2 为 0 时 `0x50` 无意义，不要显示；
- 保持期 500 ms（25 000 000 个 50 MHz 周期），期内 `0x54` bit0 = 1。

#### 2.3.3 AXI4-Stream 与 UDP

- 波束音频：16 bit，约 97.7 kB/s，给 PS 做识别，同时是 PC 声纹的音频来源；
- 8 路复数谱：64 bit/字，8×512 字/轮，约 3.1 MB/s，是 AXI-Stream 的设计目标；
  当前发布版未把 8 路复数谱完整网传，PC 频谱改由 PS 对波束音频做 256 点 FFT、
  随 JSON 下发 129 个频点（dBFS）；
- 板端 UDP 发往 PC `192.168.1.100:9000`，报文为 JSON v3，`kind` 取
  `doa`、`classification` 或 `spectrum`；PC 端另接收 `AUD3` 二进制音频包
  （JTAG 音频桥注入或板端直发），实现见 `src/pc/pc_rx/pc/radar_protocol.py`。

接口的每一次变更（新增 `0x50/0x54` 即属此类）都必须同时更新
`pl_ps_interface.md`、`handoff_tdoa_to_ps.md` 与 `board/manifest.json` 的版本号，
否则 PS 与 bit 会版本错配。

## 三、阵列信号处理原理与实现

### 3.1 均匀圆周阵列模型

8 个阵元均匀分布在半径 R = 50 mm 的圆周上，第 i 个阵元的方位角
α_i = i × 45°，i = 0…7。远场平面波以方位 θ 入射时，导向矢量为

```
a_i(θ, f) = exp(−j · kR · cos(θ − α_i)),   k = 2πf / c,  c = 343 m/s
```

相邻阵元间距 d = 2R·sin(π/8) ≈ 38.3 mm。空间混叠条件 d < λ/2 对应
f < 4481 Hz，本项目最高分析频点 4100.8 Hz，不混叠。

### 3.2 宽带非相干 MVDR

对每个频点 f_b 估计协方差 R_b，计算空间谱

```
P_b(θ) = 1 / (a_bᴴ(θ) · R_b⁻¹ · a_b(θ))
```

8 个频点的空间谱非相干相加 `P(θ) = Σ_b P_b(θ)`，取最大值对应角度为 DOA。
RTL 中直接最小化分母 `aᴴR⁻¹a`，避免除法。

### 3.3 频点选择

| bin | 频率 / Hz | kR |
|---|---|---|
| 5 | 476.9 | 0.437 |
| 10 | 953.7 | 0.873 |
| 15 | 1430.5 | 1.310 |
| 20 | 1907.4 | 1.747 |
| 25 | 2384.3 | 2.184 |
| 31 | 2956.6 | 2.708 |
| 37 | 3528.8 | 3.232 |
| 43 | 4100.8 | 3.756 |

选择原则是让 kR 在 0.44–3.76 之间尽量拉开，使各频点栅瓣去相关。
单音若落在两个 bin 之间会损失能量（不加窗），这是已知代价；宽带声不受影响。

### 3.4 协方差的遗忘因子更新

```
acc ← acc − (acc >>> S) + m
```

m 为当前快拍的外积，S 为遗忘因子指数。S=7 时时间常数约 128 个快拍（1.34 s），
静止声源精度高；检测到能量瞬态或信号消失时切 S=3（τ ≈ 84 ms），快速释放旧方向。
累加器不归零，只在复位时清零，因此不存在块平均的边界阶跃。

### 3.5 FPGA 实现架构

```
I2S×8 → i2s_rx_8ch → i2s_fft8_axis → FFT512 → bin_extract_8ch
      → cov_accum_8x8（EMA，8 套累加器）
      → cov_to_q16（1 份，前置 8:1 R 选择器）
      → mat_inv_8x8（1 份，序列复用 8 次）
      → mvdr_sweep（361 角度 × 8 bin 融合）
      → 输出级（GATE / SLEW / 瞬态窗口）→ doa_deg

I2S×8 → 一阶差分 → 7 点滑动和 → 快/慢双包络 → 触发检测
      → 256×128 bit 环形缓存 → [trig−PRE, trig+POST) 窗口
      → 局部峰 → 相对门限 → 首达沿 + 6 bit 插值
      → 通道掩码 → 加权最小二乘 → 相干度门控 → CORDIC atan2
      → tdoa_doa / tdoa_status
```

| 模块 | 份数 | 复用方式 |
|---|---|---|
| `cov_to_q16` | 1 | 前置 36×64 bit 8:1 选择器 |
| `mat_inv_8x8` | 1 | 序列状态机，bin 0→7 依次复用 |
| `steer_rom` | 8 | 36 BRAM，资源富余不复用 |
| `cov_accum` | 8 | 寄存器 + 串行 MAC，288 拍/快拍 |

### 3.6 输出级：抑制单帧离群与显示跳变

原始 MVDR 每 21 ms 给出一个角度，在噪声和瞬态下会单帧跳变。输出级做了三层处理：

1. **GATE（离群剔除）**：新角度与当前显示角相差 ≤20° 直接接受；否则需要连续
   3 帧落在 ±10° 内才切换；连续 8 帧不接受则强制放行，防止死锁。
2. **SLEW（显示限速）**：每帧最多移动 8°；超过 45° 的大幅移动放宽到 25°/帧。
3. **瞬态窗口 + 峰值相对门限**：检测到能量瞬态（拍手）时开启 32 帧窗口，
   窗口内只接受峰值 6 dB 以内的帧，且禁用强制放行，避免能量衰减期的噪声把
   显示角拖走。

上述逻辑先在 Python 中做逐位整数回放（`sim/model/sim_clap_smooth.py`），
再与 RTL 参数自动比对（`param_check.py`），最后才进综合。

### 3.7 排障记录

`report/doa_jump_investigation.md` 记录了「固定方位拍手、输出角度大幅跳变」
从现象到根因的完整过程，包括一个真实的 4 bit 计数器回绕缺陷（禁用强制放行后
计数器溢出到 0，导致强制放行永久失效）。该文也是本项目「先建模、再改 RTL」
工作方式的来源。

### 3.8 瞬态拍手：脉冲前沿 TDOA 支路

#### 3.8.1 为什么 MVDR 在拍手上失效

拍手持续约 1 ms，而 FFT 窗是 512 点、10.7 ms。一帧里同时包含拍手前的噪声、
拍手本身和房间反射，协方差矩阵被噪声与反射污染，单帧空间谱的峰位方差大；
再加上能量在几帧内迅速衰减，输出级看到的就是「角度乱跳」。这不是平滑参数
没调好——把 `data/clap_log_20261101.csv` 按能量峰值对齐后可以看到，峰值帧
其实是稳定的（140–142°），漂移发生在能量掉了 12 dB 之后。

因此解法不是继续调 MVDR，而是给瞬态单独开一条时域支路：**只用首达沿**，
它由直达声决定，与后续反射和衰减无关。

#### 3.8.2 算法流程

| 步 | 处理 | 参数 |
|---|---|---|
| 1 | 通道差分 `|x[n]−x[n−1]|` | 削弱低频与直流，突出前沿 |
| 2 | 7 点因果滑动和 | `>>3`，群延迟 3 样本，8 路相同不改变相对时差 |
| 3 | 快/慢双包络 | 快 τ≈4 样本，慢 τ≈4096 样本 |
| 4 | 触发判定 | 快包络超绝对下限，且 `e_f/4 > 4·e_s/4096`；预热 0.5 s 后才允许触发 |
| 5 | 环形缓存 | 256 样本 × 128 bit，触发后取 `[trig−32, trig+96)` 共 128 样本 |
| 6 | 局部峰 | 在窗内 `[PRE−12, PRE+40]` 找最大 |
| 7 | 门限 | `max(peak/4, 4×trig 时刻慢包络)`，抗拖尾与底噪 |
| 8 | 首达沿 | 窗内第一次跨过门限的位置，6 bit 线性插值 |
| 9 | 通道掩码 | 峰值低于 `pmax/8` 的通道剔除，少于 5 路不出结果 |
| 10 | 加权最小二乘 | `A=Σw·d·cosα`，`B=Σw·d·sinα`，`θ=atan2(B,A)` |
| 11 | 相干度 | `coh²=2(A²+B²)/(sw·Σw·d²)`，理想平面波 ≈ 1，乱时刻 ≈ 0.25 |
| 12 | 门控 | `coh²<0.75` 或 `sw<5` 时置 `lowconf=1`，顶层不采用 |

几个参数是调出来的，不是理论值：

- **7 点而不是 5 点**：5 点平滑后弱拍前沿仍有抖动；7 点把前沿单调化，
  弱拍（45 dB）从「误差 3–4°、偶发 lowconf」变成「89°、lowconf=0」；
- **相干度 0.75 而不是 0.6**：0.6 时纯噪声偶发通过；0.75 在 8 方向回放全部
  通过，5 s 纯噪声 0 次误触发；
- **至少 5 路**：8 路（45° 间隔）中任意 5 路即可唯一确定方位，少于此数
  加权最小二乘会退化成两个候选解。

角度由 16 次迭代 CORDIC `atan2` 算出，输出 Q8 度；1 个采样点的时差约对应
8°，所以插值精度直接决定角度精度。

#### 3.8.3 一个只有 RTL 回放才能抓到的 bug

首版回放时 `A`、`B` 都与预期一致，但 `doa=90 lowconf=1`、`coh_ok=0`，
`sd2=343069039807`，比正常值大约 5×10⁵ 倍。根因是：

```verilog
sd2_acc <= sd2_acc + dval * dval;   // sd2_acc 为 unsigned，dval 为 signed
```

负的 `dval` 被零扩展成接近 `2^18` 的大正数，平方后爆炸，相干度恒为 0，
顶层因此**从未采纳过 TDOA 结果**。改成：

```verilog
reg signed [39:0] sd2_acc;
sd2_acc <= sd2_acc + ($signed(dval) * $signed(dval));
```

后 `sd2≈6.5×10⁵`、`coh_ok=1`、`lowconf=0`。

Python/NumPy 模型不会复现这个 bug（整数会自动提升为有符号），所以这一条
是「必须做 RTL 逐位回放、不能只信 Python」的直接证据，也是技能包
`skill/transient-tdoa-first-arrival/` 的核心案例。

#### 3.8.4 与顶层的集成

- 结果暴露到 AXI：`0x50 TDOA_DOA`（9 bit 有符号）、`0x54 TDOA_STATUS`
  （bit0 保持中、bit1 上次低置信、bit2 已有结果）；
- 保持 500 ms（25 000 000 周期）内顶层选择 TDOA 角度，之后回 MVDR；
- 触发后约 2.1 ms 出角度，远小于一帧 MVDR 的 21 ms，适合实时显示；
- PS 侧显示逻辑与 C 代码见 `report/handoff_tdoa_to_ps.md`。

#### 3.8.5 验证结果

RTL 逐位回放（含 1–2 条反射、通道增益/时延失配、0.5 s 预热）：

| 场景 | 真实角度 | RTL 输出 | 误差 | lowconf | coh_ok |
|---|---:|---:|---:|---:|---:|
| 四基准方向 | 0° / 90° / 180° / 270° | 0° / 90° / 180° / −90° | 0° | 0 | 1 |
| 任意方位 | 37° | 36° | 1° | 0 | 1 |
| 任意方位 | 217° | −140°（=220°） | 3° | 0 | 1 |
| 40 dB | 0° | 0° | 0° | 0 | 1 |
| 45 dB 弱拍 | 90° | 89° | 1° | 0 | 1 |
| 30 dB 纯噪声 5 s | — | 无触发 | — | — | — |

复现命令与完整打印见 `sim/results/tdoa_replay_summary.md`。需要强调：
**这是 RTL 行为验证，不是上板精度。** 上板还要面对安装偏移、通道一致性、
房间混响与风噪，数据按 `data/tdoa_board_summary.md` 单独采集。

#### 3.8.6 边界

- 声源与阵列不同高 / 不在同一平面时，时差模型不成立，角度系统性偏；
- 强混响下首达沿被反射淹没，第一次跨阈值的位置不是直达声；
- 拍手离麦太近会削顶，前沿变平，6 bit 插值失效；
- 多个瞬态同时发生会给出「中间角」；
- 阵列半径、采样率、阵元角度变化后 `k`、`max_tdoa`、各级阈值都要重算。

## 四、波束成形与声源识别

### 4.1 先粗后精双通道

- **DAS 粗测**（寄存器 0x20）：时域分数延时求和，宽带任意声音可用，
  ~21 ms 更新，实测 ±2–3°。
- **MVDR 精测**（寄存器 0x08）：47.7 Hz 连续刷新，连续声源 ±1–2°。
- **瞬态 TDOA**（寄存器 0x50/0x54）：只对拍手等短促瞬态生效，触发后
  约 2.1 ms 出角度，保持 500 ms。

前两者同时提供，PS 可先粗锁定再精确认；第三路由触发事件驱动，不参与
连续声源的常规显示。

### 4.2 波束形成

按当前 DOA 对 8 路做分数延时求和，得到增强后的单路音频。
仿真中正确角 RMS 8305，理论值 8485（98%）；错角 90° 时压制 7.1 倍（≈17 dB）。

### 4.3 声源识别

PS 端对波束音频做 2 s 窗口、100 ms 步进的 MLP 推理：

- 输入 144 维特征（【待补】具体特征定义与提取方式，见 `src/ps/src/`）；
- 结构 144 → 64 → 32 → 9，ReLU；
- 9 类：拍手、说话、钢琴、鸟叫、狗叫、鸣笛、流水、拉链、敲键盘；
- 拒识：top1 ≥ 0.8 且领先第二名 ≥ 0.05，否则输出「不确定」；
- 候选集测试准确率约 67.6%。

【待补】混淆矩阵、真实环境误识别率、各类别样本数。

### 4.4 双路 AXI-Stream

| 流 | 位宽 | 速率 | 用途 |
|---|---|---|---|
| 波束音频 | 16 bit | 97.7 kB/s | PS 识别 |
| 8 路复数谱 | 64 bit | 3.1 MB/s（32 KB / 10.49 ms） | PC 可视化（设计目标，当前发布版未启用） |

## 五、可视化与通信

### 5.1 链路

PL → AXI4-Lite 寄存器（角度/能量）与 AXI4-Stream（波束音频/频谱）→ PS 组包 →
UDP 9000 → PC。报文为 JSON v3，包含 `doa`、`classification`、`spectrum` 三类消息；
PC 另接收 `AUD3` 二进制音频包（由 JTAG 音频桥从 PS DDR 环形缓冲取出，或板端直发）。
PC 端源码与运行说明见 [`src/pc/`](../src/pc/README.md)。

### 5.2 显示内容

网页大屏为单文件 `src/pc/acoustic-radar.html`，四个面板：

1. **方位雷达**：只显示 PL 的 MVDR 精确结果，不使用 DAS；连续 2 秒没有新包标记
   “数据超时”。指针按拟合角速度平滑扫过板端约 750 ms 的数据空档，静止时
   ±1–2° 抖动由 2.5° 死区滤除，快速换位（>20°）在 15 ms 内跟上。
2. **声音类别**：七类标签 + “安静 / 不确定”，事件上报后 0.5 秒内显示并置顶。
3. **实时频谱**：PS 对波束音频做 256 点 FFT，下发 129 个频点（0–8000 Hz，dBFS）
   与活动标志，约 10 包/秒。
4. **声纹**：PC 端 CAM++ 中文预训练模型提取 192 维嵌入，与声纹库做 1:N 余弦比对，
   阈值 0.35；说话期间取最近 2.5 秒滑窗，多窗多数表决并锁定结果，避免单窗抖动；
   首次亮名前要求连续两窗一致。录入为 3 段 × 4 秒阵列音频。

传输采用 SSE 事件驱动推送：新包到达立即唤醒推送线程（实测 <10 ms），状态无变化时
每秒心跳。PC 端不替代 PS 的方位/分类计算；声纹推理是真实的 CAM++ 前向，不使用
模拟数据。瞬态 TDOA 的上位机显示尚未接入，待 PS 固件并入 `0x50/0x54` 后按
[`report/handoff_tdoa_to_ps.md`](handoff_tdoa_to_ps.md) 扩展。

异常处理：拔网线 2 秒内显示“PS 数据超时”；阵列音频断流 >1.5 秒时声纹面板回落
“未识别到人声”，不使用冻结的旧音频打分。实测数据见
[`src/pc/verification/results.md`](../src/pc/verification/results.md)。

> 早期方案中的“8 方位波束谱”未在当前发布版实现；实际部署的是上述 129 频点
> 单路频谱。设计设想见 `report/spectrum_display_design.md`，两者不要混写。

### 5.3 角度映射

导向 ROM 使用 `th = ang − 180°`，板上显示角 = 模型角 + 180°（安装偏移）。
该偏移在联调中实测确认，写入接口文档，避免 PC 端重复踩坑。

### 6.3.1 优化前后对比

#### 算法与行为

「优化前」指基线 bit：拍手由 8 bin MVDR 估计，输出级只有 GATE / SLEW / 瞬态
窗口；「优化后」指 `src/pl/rtl/` 的 TDOA 支路。

| 维度 | 优化前（MVDR + 输出级） | 优化后（TDOA 支路） |
|---|---|---|
| 瞬态角度来源 | 10.7 ms FFT 窗的空间谱峰 | 首达沿的通道间时差 |
| 受反射/衰减影响 | 大：峰位随窗口内噪声比例变化 | 小：只用首次到达 |
| 首次出角延迟 | 21 ms 量级（一帧），且需多帧稳定 | 约 2.1 ms |
| 跨次一致性 | 同一方位多次拍手可能相差数十度 | RTL 回放 8 方向误差 ≤1°，任意角 ≤3° |
| 置信度输出 | 无专用置信度，靠能量门限 | `coh²≥0.75` 且 `sw≥5`，否则 `lowconf=1` |
| 对连续声源 | 正常 | 不触发，显示仍走 MVDR |
| 证据 | `data/clap_log_20261101.csv`（单次逐帧记录） | `sim/results/tdoa_replay_summary.md`（RTL 回放 8 向量） |

段漂移；优化后的数字是 RTL 回放，**两者不是同一测试条件**。同一条件下的
上板前后对比必须等 TDOA 版 bit 生成后，按 `data/tdoa_board_summary.md` 采集，
不能用回放数字代替。

| 项目 | 基线（2026-10-22） | TDOA 版（2026-11-03） | 变化 |
|---|---:|---:|---:|
| 顶层 | `radar_pl_top` | `radar_pl_bd_verify_top` | 验证顶层不同 |
| LUT | 29 130 (54.8%) | 35 354 (66.45%) | +6 224（+11.65 pt） |
| FF | 37 545 (35.3%) | 40 674 (38.23%) | +3 129（+2.93 pt） |

读法：

- 资源增量主要来自 256×128 bit 环形缓存（32 Kbit，约 1 个 36Kb BRAM）、

- **两次实现的顶层不同**（基线是 `radar_pl_top`，TDOA 版是带 AXI 接口的

  不能全部归给 TDOA 支路；
- 即便如此，LUT 66.45% 仍有约 1.8 万 LUT 余量，时序余量反而从 +0.680 ns
  增加到 +0.798 ns（综合指令 `AreaMultThresholdDSP`、布线差异所致）。

原始 `.rpt` 在 `build/reports/`，导出方法见 `build/export_reports.tcl`。
若后续重跑，以该目录最新报告为准并同步更新本节。

### 6.4 已知局限

- 拍手等瞬态声源：MVDR 路径本身仍有跨次方差（一次拍手约 1 ms，FFT 窗 10.7 ms）。
  现用 TDOA 支路规避，但该支路只在一维圆周平面、同高度、中低混响下成立；
  强混响、多瞬态同时发生、离麦过近削顶时仍会失准。
- TDOA 支路目前只有 RTL 回放证据，尚未上板；安装偏移与通道一致性会带来
  回放中不存在的系统误差，需按 `data/tdoa_board_summary.md` 实测。
- TDOA 版已完成综合/实现（`radar_pl_bd_verify_top`，数字见 6.3.1），但尚未
  打包进 `board/payload/` 的发布 bit/ELF，也还没有与 PS 联调的整板数据。
- 8 个离散频点不是连续频带，单音落在 bin 之间会损失能量。
- 未做通道幅相校准，测向精度受麦克风一致性限制。
- 识别模型为 MLP，候选集准确率约 67.6%，不代表真实环境性能。
- `board/payload/` 的 bit/ELF 是 2026-10-28 基线，不含 TDOA 与输出级优化。

## 七、总结与展望

### 7.1 创新回顾

1. 8 频点宽带非相干 MVDR + 自适应遗忘因子；
2. 算子时分复用把 8 倍算力压进一片 XC7Z020；
3. PL / PS / PC 三段异构分工与双路数据流；
4. 连续 MVDR 与瞬态前沿 TDOA 双支路并存，用「首达沿」把瞬态定位从
   空间谱域转到时域，并以相干度门控防止噪声被误当成拍手。

### 7.2 可扩展方向

- 通道幅相校准（一次性系数存 ROM）；
- 8 方位波束谱下放 PL；
- 更多频点 / 更宽频带；
- 板载 LCD 脱机显示；
- 多声源 TDOA 分离与跟踪。

### 7.3 心得

本项目最耗时的一步不是写 RTL，而是确认「现象到底是什么」。最初把「角度跳变」
归因为显示轨迹不够平滑，改了限速参数，问题依旧；直到把每次拍手的逐帧记录
导出、按能量峰值对齐，才发现峰值帧其实稳定，漂移发生在能量衰减之后的噪声段。
结论是：先建立可复现的逐帧数据，再改逻辑；每次改完用逐位回放模型对比 A/B，
最后才上板。完整的排障过程见 `report/doa_jump_investigation.md`。

## 八、大模型协作记录

### 8.1 协作方式与边界

本项目使用大模型（Claude Code）承担四类工作：读代码与日志、提出假设、生成

### 8.2 案例一：拍手角度跳变的根因

| 项 | 内容 |
|---|---|
| 现象 | 固定方位拍手，板上角度在 52°→140° 之间跳，随后持续漂移 |
| 初始假设（错误） | 显示限速/GATE 参数不够平滑，想调大窗口 |
| 用户提示词 | 「请你先不要改我的代码部分，先想办法查明。」 |
| 模型动作 | 要求导出逐帧记录，按能量峰值对齐；发现峰值帧 140–142° 稳定，漂移发生在能量掉 12 dB 之后 |
| 结论 | 不是平滑问题，是协方差在信号消失后仍在吸收噪声，门控仍放行 |
| 验证 | `sim/model/sim_clap_smooth.py` 逐位回放 A/B/C 三变体；`data/clap_log_20261101.csv` |
| 自我纠正 | 放弃「调限速」方案，改为「峰值相对门限 + 窗口内禁用强制放行」 |

这个案例也暴露了一个 4 bit 计数器回绕缺陷：禁用强制放行后计数器溢出到 0，
强制放行永久失效。它是在建模回放里先发现、再改 RTL 的。

### 8.3 案例二：`sd2_acc` 的有符号 bug

| 项 | 内容 |
|---|---|
| 现象 | TDOA 首版回放 `doa` 正确但 `lowconf=1`，顶层从不采纳结果 |
| 模型动作 | 生成 `tb_tdoa_replay.v` 与 8 方向向量，逐位跑 xsim，打印 `A/B/ab2/sd2/coh_ok` |
| 关键观察 | `A/B` 正常，`sd2=343069039807`，比预期大约 5×10⁵ 倍 |
| 模型给出的根因 | `dval` 为 signed、`sd2_acc` 为 unsigned，负值被零扩展后平方爆炸 |
| 人工判断 | 与代码逐行核对，确认位宽与符号声明 |
| 验证 | 改为 `reg signed [39:0]` + `$signed()` 后 `sd2≈6.5×10⁵`、`coh_ok=1` |
| 自我纠正 | 此前认为「Python 模型能代表 RTL」，此案之后改为「Python 定策略、RTL 回放定行为」 |

### 8.4 案例三：Vivado 综合「卡死」

| 项 | 内容 |
|---|---|
| 现象 | 综合两小时，实际综合时间只有 23 分钟，界面无输出 |
| 用户提示词 | 「这综合是不是进入死循环了，综合了两个小时实际综合时间只有 23 分钟呢。」 |
| 模型动作 | 读 `runme.log`、`exception.log`，查 worker 进程的内存/CPU、检查 `__synthesis_is_running__` 残留 |
| 关键观察 | worker 提交内存高、工作集极小、CPU 增量为 0，日志停在同一步 |
| 结论 | 不是 RTL 死循环，是综合进程卡在子步骤/权限错误上；需清理残留锁与运行目录后重跑 |
| 验证 | 用 `build/check_vivado.ps1` 的判据复查（CPU 与日志同时不涨 = 挂死）；重跑结果以 `build/reports/` 的 `.rpt` 为准 |

### 8.5 Agent 工作流

长工程里真正省时间的是「把可并行的取证拆开」：

1. **只读侦察**：先让子代理并行读 RTL、日志、历史 CSV，返回结论与文件位置，
   不返回大段代码；
2. **假设收敛**：由人从候选原因中挑 1–2 个，模型只对这几个写最小回放；
3. **回放取证**：每个假设配一个可复跑脚本/testbench，输出打印数值；
4. **改动留痕**：改 RTL 前备份、改完给 diff，文档与技能同步更新。

反面做法是把整个工程丢给模型「帮我修好」，结果往往是改了不相关文件、
或者把现象解释得很合理但没有证据。本项目所有结论都能指回一个文件。

### 8.6 可复用的提示词

```text
这是我的工程 <路径>。现象是 <可观察事实>。
先不要改代码：请读 <文件/日志>，列出可能原因，按可能性排序，
每条说明你依据哪一行/哪个数值，以及用什么最小实验可以证伪。
```

```text
按你上面第 <n> 条的假设，写一个最小回放 testbench/脚本，
只验证这一条，打印 <具体信号>，不要改 RTL。
```

这两条模板的完整版与更多例子见 `skill/fpga-ai-collaboration/` 与
`report/ai_collaboration_log.md`。

## 九、技能包提炼过程

### 9.1 从故障到技能

技能不是把教科书章节改个名字，而是把**本项目真实踩过的坑**固化成
「适用场景 / 使用方法 / 已验证效果 / 失效条件 / 来源」五项。

| 原始故障或观察 | 提炼出的技能 | 验证方式 | 失效条件（摘要） |
|---|---|---|---|
| 改输出级后只能靠综合+上板确认 | `rtl-bit-exact-replay/` | Python 逐位回放 + xsim testbench | 只覆盖控制逻辑，不覆盖数值通路 |
| 仿真正常、上板丢数 | `axi-stream-tlast/` | 波形 + DMA 计数 | 多路广播/独立背压时不适用 |
| 协方差秩亏、方向漂移、拍手拖尾 2.5 s | `mvdr-covariance-ema/` | 对角加载与 S 切换的 A/B 回放 | 强相关源、非平稳噪声下需重新标定 |
| 综合长时间无输出、机器卡顿 | `vivado-synth-hang/` | 进程内存/CPU、日志与锁文件 | 真正的长综合不适用，需先排除规模 |
| 模型改了不相关文件、结论无证据 | `fpga-ai-collaboration/` | 「先取证、再改」流程与提示词模板 | 不替代人对硬件的判断 |
| 拍手角度跨次跳变 | `transient-tdoa-first-arrival/` | 8 方向 + 弱拍 + 纯噪声 RTL 回放 | 强混响、非共面、多瞬态 |
| PS/PL 联调反复踩复位、DMA、定时器、载荷配对 | `ps-pack/`（PS 侧整理） | 原始日志 + `MANIFEST_SHA256.json` | 换 PS 平台/协议后需重验 |

### 9.2 提炼规则

1. **只写踩过的坑**：没有真实证据的条目不进技能包；
2. **数字必须能指到文件**：每个结论后面跟仓库内路径；
3. **必须写失效条件**：没有失效条件的技能，通常意味着还没真正踩过；
4. **换参数必须重算**：`k`、窗口、阈值、协议槽位都随器件/阵列/平台变化；
5. **保留原始证据**：PS 技能包带 `MANIFEST_SHA256.json` 与 `verification_record.json`，
   防止结论在转述中失真。

### 9.3 零基础复现

从零复现的完整步骤见根目录 `REPRODUCE.md`，它按「硬件 → 软件 → 综合 →
导出报告 → PS → 上板 → 离线回放 → 上板 TDOA」的顺序写，每一步给出预期输出
与失败排查。技能包解决「为什么这么做」，`REPRODUCE.md` 解决「具体敲什么」。
