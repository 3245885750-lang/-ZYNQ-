## 二、本次改动对显示角度的作用上限

超前补偿：`θ_out = θ_raw + 3·Δθ`（静止时 Δθ=0 严格不起作用）。
把静止声源的原始估计当 iid 抖动过一遍门控（`sim/sim_pred_noise.py`，20000 帧 × 5 种子）：

| 原始抖动 σ_raw | 补偿后 σ_out | 放大 | 门控通过率 | 步长 RMS 原→后 |
|---|---|---|---|---|
| 0.5° | 0.85° | 1.71× | 2.2% | 0.71° → 1.22° |
| 1.0° | 2.29° | 2.30× | 11.0% | 1.41° → 3.27° |
| 2.0° | 4.19° | 2.10× | 17.6% | 2.82° → 5.88° |
| 3.0° | 5.55° | 1.86× | 17.4% | 4.23° → 7.73° |
| 5.0° | 7.73° | 1.55× | 13.7% | 7.06° → 10.80° |
| 8.0° | 10.02° | 1.26× | 9.0% | 11.29° → 14.07° |

即：**原本就抖的静止声源，显示抖动会变成 1.3–2.3 倍**（1°–2° 这一档最坏）。
但门控要求 `|Δθ| ≤ 10°` 且两帧同号，单帧被放大的增量最多 30°，
输出步长最大约 20°——**这段补偿在数学上造不出 180° 的跳变**。

## 三、逐项排除（全部是模型实测，不是估计）

统一场景：静止单音、10–20 s、UI 口径统计"5 s 窗口内 |步进|>30° 的次数"。

| 机理 | 脚本 | 结果 | 判定 |
|---|---|---|---|
| 信噪比太低 | `sim_bin43_snr.py` | 30dB→0.0 次；10dB→0.0；0dB→0.1；−5dB→3.9 次 | 排除（差一个量级） |
| EMA 记忆长度 | `sim_mem_forced.py` | bin43 在 S=7/5/4/3 下都是 1.9°/1 跳 | 排除 |
| 通道幅相不一致 | `sim_sens.py` | ±5% 幅度 /±10° 相位：偏置 <0.2°、RMS 2.8–4.0° | 排除 |
| 近场（平面波 ROM 估近场源） | `sim_nearfield.py` | 2 m/1 m/0.5 m/0.3 m/0.2 m 与远场几乎完全相同（bin43 RMS 1.8–2.1°） | 排除 |
| 新老判据差异 | `sim_mismatch.py` | bin43 下两条规则结果一致（5.0°/1 跳） | 排除 |
| 相干直达 + 一次墙面反射（反射相位漂移） | `sim_multipath.py` | 最坏 γ=0.6、随机游走相位：bin43 5.3 次/5s | **只能解释约 1/10** |

> `sim_nearfield.py` 的约定由暴力扫描锁定（`sim_nf_check.py`）：`exp(−jkd)` + 源角取 ROM 索引本身，
> r→∞ 时与 `A` 的距离 = **0.00000**。相位符号或源角写反会让估计落到镜像/共轭，误差恒定 180°——
> 本报告早期版本踩过这个坑，用控制组（远场）挡掉了。

**没有一项能把 55 次/5s 复现出来。** 剩下没建模的只有"真实房间的多径+时变"，
而这恰好也是最有解释力的一项（5.3 次/5s 已是最接近的量级）。

## 四、闸门从"两帧"改成"连续 N 帧"

第二节说明补偿对静止抖动的放大来自**闸门太松**：两帧一致的判据在 iid 噪声上的通过率有 3%~13%，
这些帧被放大 3 倍。匀速运动的增量是帧帧同号、大小相近的连续序列，静止噪声做不到——
所以把闸门扩到"最近 N 帧全部同号、都在 1°~10°、极差 ≤ 3°"。

`sim/sim_pred_nframe.py`（5 种子 × 2 万帧；G=3、tol=3° 沿用旧结论）：

| 原始抖动 σ | 不补偿 | N=2（已烧那版） | **N=4** |
|---|---|---|---|
| 1° | 1.00° | 1.49°（通过 3%） | **1.00°（通过 0%）** |
| 2° | 2.00° | 3.72°（11%） | **2.01°（0%）** |
| 3° | 3.00° | 5.31°（13%） | **3.02°（0%）** |
| 5° | 5.00° | 7.62°（12%） | **5.01°（0%）** |

环绕代价（宽带 8bin、3 种子、运动段 RMS）：

| 速度 | 不补偿 | N=2 | **N=4** |
|---|---|---|---|
| 90°/s | 9.4° | 6.1° | **6.5°** |
| 180°/s | 11.4° | 6.5° | **7.1°** |
| 270°/s | 14.8° | 10.1° | 12.3° |

结论：N=4 在静止噪声上是**结构性不触发**（σ 从 1° 到 5° 通过率全为 0），而环绕仍拿走大部分滞后补偿。
N=6 在静止上同样是 0%，但 90°/s 只能到 6.8°、270°/s 掉到 13.5°，不划算。

RTL 已按 N=4 实现（`dh0/dh1/dh2` 三拍历史 + 当前帧，`inwin`/`same_sign`/`range_ok` 三个条件）。

## 四之二、通道时延差（频率相关的流形误差）—— ⚠ 已被板上结果否定

> **2026-10-31 板上实测：2.5k / 3.5k / 4.1k 三个频点各 10 s，全部无跳变，最大步进 1.0°。**
> 本节机理是"几何/频率相关"的，任何固件都改不了它。4.1k 既然稳，本节假设**不成立**，
> 保留数据仅作排查记录，不能作为修复依据。下面第六节据此重排。

前面所有测试都有一个共同错误：通道不一致我用的是**固定相位误差**（±10°、与频率无关）。
真实来源是**时延差 Δt**，等效相位误差 = 2πf·Δt，随频率线性增长：

| Δt | 1 kHz | 2 kHz | 4.1 kHz |
|---|---|---|---|
| 30 µs | 11° | 22° | 44° |
| 60 µs | 22° | 43° | 89° |

而 bin43 的 kR = 3.756，相邻阵元最大相位差 **165°**，离 180° 的空间模糊边界只剩 15° 余量。
时延差把导向矢量推过这条线，MVDR 谷底就落到任意方向。

`sim/sim_delay_mismatch.py`（稳定单音 90°、25dB、8 s、3 种子）：

| 通道时延差 | bin10 | bin20 | bin31 | **bin43** |
|---|---|---|---|---|
| 0（理想） | 2.6° | 3.5° | 0.5° | 4.5° |
| ±30 µs | 3.9° | 5.4° | 2.7° | 6.6° |
| **±60 µs** | 6.5° | 8.0° | 8.0° | **82.5°（66% 的帧偏 >45°）** |

**这是第一个能同时解释"高频崩、低频稳"和"崩得很厉害"的机理**，并且与补偿、记忆长度、判据完全无关。

`sim/sim_calib_fix.py` —— 逐通道标定能不能救，以及标定要多准：

| 标定残差 | bin43 RMS | 偏 >45% 的帧 |
|---|---|---|
| 不标定 | 22.3° | 32.3% |
| ±20 µs | 3.4° | 0.1% |
| ±10 µs | 3.1° | 0.1° |
| 完全标定 | 3.0° | 0.1% |

同样是 ±60 µs 未标定，各 bin：bin10 5.6°、bin20 4.0°、bin25 4.3°、bin31 6.4°、bin37 5.1°、
**bin43 22.3°**。即悬崖出现在最后一个 bin，与前 7 个无关。

**尚未确认的是这只板上的真实通道误差有多大**——这需要真实数据（见第六节第 1 条），
不能靠模型断言。±60 µs 相当于 2 cm 的空气路径差，对 8 麦手装圆周阵列是可能的（单个麦位置偏差），
但也有可能实际误差更小、崩掉另有原因。

### 六.1 先纠正一个可能一直存在的数据误读

`tools/doa_view.py` 的统计口径（已核对源码）：

| 项 | 代码行为 |
|---|---|

### 六.2ter 怎么分开"麦克风坏"和"FFT 坏"（不烧录）

板上有现成的独立证人：**`led1`**。

```

radar_pl_top.v:147  DAS 用的是 .sample_data(ads_data) —— I2S 原始采样，不走 FFT
```

### 8.6 冷启动抑制的实现与离线验证

**改动**（`fft_demo/src/mvdr_axi_top.v`，只动这一个文件）：

| 项 | 值 | 说明 |
|---|---|---|
| `WARM_EN` | 1 | 0 可整体关掉；只在 `AUTO_RUN=1` 连续模式下生效 |
| `WARM_N` | 64 | 复位后丢弃的前 64 个 DOA 帧 = 1.34 s = 1 个 EMA 时间常数（128 快拍 ÷ K=2） |

行为：

- `warm_cnt` 对每一个 `mvdr_done` 计数（饱和于 `WARM_N`，8 bit 够用）；
- `warm_cnt < WARM_N` 时**不更新** `doa_out_reg / dh0 / dh1 / dh2 / smin_reg / shift_reg`，
  也不发 `doa_done` —— 即上位机看不到这几帧（`mvdr_print = doa_done & sig_present`，
  所以不是"显示旧值"，而是真的不发）；
- `doa_reg <= doa_w` **不受门控**：运动检测器读的是 `doa_reg`，让它从第一帧就跟着
  `doa_w` 走，热身后第一次出数时门控历史已经是正确的，不会额外多等 4 帧；
- `done_sticky` 与状态机跳转不受门控，`AUTO_RUN=0` 单次模式完全不走这条路径。

**离线验证**（`fft_demo/sim/sim_warm_gate.py`，输入是 17:05 那次真实板上 CSV 的头 8 s）：

```
抑制前（现状）：显示 383 帧，>30° 跳变 4 次，最大步进 169°
  前 10 帧角度：92 92 92 92 257 66 311 91 91 91
  WARM_N=16 → 跳变 0 次，首个输出 91°
  WARM_N=32 → 跳变 0 次，首个输出 90°
  WARM_N=64 → 跳变 0 次，首个输出 89°
```

抑制只丢复位后前 `WARM_N` 帧，其后的输出与不带抑制时**逐帧相同**（脚本逐值比对），
所以对静态精度、实时性都没有影响，代价只有上电后 1.34 s 不出角度。

## 8.7 运动判据 v2 的模型验证（2026-10-31 晚）

### 8.7.1 为什么 v1 判据在快转时自己失效

v1 是在"上一帧输出角 θp ±12°"上比波束功率。转速一高 θp 被拖后，真实声源一直贴在
θp+12° 附近，比值 r 上不去 ⇒ 判据只在**慢速**时才认得出运动。模型里"判据认为在动"
的时间占比：15°/s 12%、60°/s 37%、100°/s 52% —— 和实测量级一致。

### 8.7.2 v2 判据

用前导补偿本来就算了的角度增量 d1（`mvdr_axi_top.v:295`，已做 ±180° 环绕）：

```
m ← m − m/2^SH + d1          稳态匀速时 m ≈ 2^SH × 每帧转角，与 θp 是否滞后无关
|m| ≥ ENTER → 置位（保持 HOLD 帧）
|m| <  EXIT → 清位；介于两者之间保持原状态（滞回）
```

### 8.7.3 模型扫描（`fft_demo/sim/sim_motion_v2.py`，单音 bin43，SNR 30 dB）

| 配置 | 15°/s | 31°/s | 60°/s | 100°/s | 宽带 60/100°/s |
|---|---|---|---|---|---|
| A sh3 2.0/1.0 h0 | 0 | 4 | 14 | 12 | 2 / 4 次/分，RMS 11.4 / 25.4 |
| B sh3 1.5/0.5 h10 | 0 | 4 | 0 | 10 | 2 / 4，RMS 11.4 / 25.4 |
| D sh4 1.5/0.5 h10 | 0 | 0 | 0 | 0 | 0 / 0，RMS 5.1 / 7.6 |
| E = v1 ∪ v2(B) | 0 | 0 | 0 | 0 | 0 / 0，RMS 5.1 / 7.6 |

（跳变 = >30° 步进，次/分钟。模型自己的静止误触发：A 0.5~3%、B 1.3~5%、D 到 20.4%——
**这一列后来被真数据证伪，见 8.7.4，不能作为依据**。）

### 8.7.4 真数据回放：B 的门限根本不能用（关键转折）

用 24.6 分钟真实静止记录 `run.csv`（36944 帧）逐帧回放 v2 的定点实现
（`fft_demo/sim/sim_mv2_rtl.py`、`sim_mv2_sweep.py`）：

| 事实 | 数值 |
|---|---|
| 相邻帧步进分布 | 0° 占 96.8%，±1° 占 3.2%，>2° 只有几十帧 |
| 非零同号连跑 | 967 段，其中 954 段只有 1 帧、9 段 2 帧、4 段 3 帧，最长 3 帧 |
| \|m\| 的分位（Q2=0.25°） | 中位 3、90% 分位 7、99% 分位 10 |
| **B（ENT=6/EXIT=2/HOLD=10）误判"动"** | **45.6%** |
| **H（ENT=12/EXIT=5/HOLD=4）误判"动"** | **1.6%** |

原因：模型里的静止 DOA 几乎是理想的（95% 分位误差 0.0°），真实板上却有 3.2% 的单帧
±1° 抖动，而且 \|m\| 的底噪就有 3~5。1.5°/帧 的门限只比底噪高一点，"偶尔跳一下"就会
越过它；再叠上滞回（状态在 EXIT 与 ENTER 之间保持），m 掉不回 0.5°/帧以下，于是一直
卡在"动"上。**门限必须抬到静止底噪之上**，v1 补慢速、v2 只负责快转，两者分工才成立。

### 8.7.5 定稿参数（已写进 RTL）

| 参数 | 值 | 含义 |
|---|---|---|
| `MV2_EN` | 1 | 与 v1 取并集；0 = 只剩 v1 |
| `MV2_SH` | 3 | 遗忘 τ = 8 帧 ≈ 0.17 s |
| `MV2_ENTER` | 12 (Q2) | m 稳态到 12 ⇔ **17.9°/s** |
| `MV2_EXIT` | 5 (Q2) | m 稳态到 5 ⇔ 7.5°/s |
| `MV2_HOLD` | 4 | 清位前保持 4 帧 ≈ 84 ms |

余量：31°/s 时 m≈21（1.75 倍）、60°/s≈40、100°/s≈67。代价是 <18°/s 时 v2 不动作，
那段仍由 v1 负责（模型 15°/s：v1 命中 12%~100%、0 次跳变，本来就不需要 v2）。

定点 vs 浮点参考：36944 帧里 261 帧（0.7%）判决不同，全部落在门限 ±0.25° 的边界上。

### 8.7.6 拍手瞬态

137° 常驻单音 + 10.00~10.12 s 从 250° 来的宽带脉冲（比噪声高 15 dB）：
判据在脉冲期间正确跟随 250°，脉冲结束后 **0.2 s 内**回到 137° 并一直停在 137；
"短记忆"标志另外延续约 1.2 s（180° 的来回让 m 衰减需要 ~30 帧 + HOLD），
但这段时间的输出角全程是 137°，没有精度损失。（用户 2026-10-31 表示拍手表现已可接受，
此项不作为改动目标。）

### 8.7.7 已知未解的限制

SNR 10 dB 时所有判据（含 oracle = 永远短记忆）结果相同：60°/s 48 次/分、100°/s 32 次/分。
也就是说低信噪比下的跳变是算法/信噪比本身的上限，不是判据的问题，v2 不改善也不恶化。

### 8.7.8 尚未验证的

模型与板上在低速段对不上（同一套 v1 判据，模型 31°/s 预测 0 次跳变，板上 41 s 实测 39 次），
所以 8.7.3 的绝对跳变数不能直接外推到板上。真正的判据只有一个：综合上板后同转速再跑一次，
用 `tools/diag_jump_energy.py` 按同一口径打分。

为了让这一次上板能直接回答"值不值得保留 v2"，串口行已加上运动判决字段：

    M=270 E=0012AB34 V=01        （23 字节；旧格式 18 字节仍能被 doa_view.py 解析）

`V=<v1><v2>`：1 = 该判据在本帧判为运动（协方差切短记忆）。于是三类现象可以分开：

| 现象 | 结论 |
|------|------|
| 跳变帧 V=00，且转速 ≥18°/s | 两个判据都没开 → 门限仍偏高，继续降 ENTER |
| 跳变帧 V=1x（v2 开） | 判据开了也没用 → 问题不在记忆长度（回到 8.7.7 的 SNR 上限） |
| 静止时 V=1x 长时间为 1 | v2 门限偏低 → 误切短记忆，静止精度会掉 |

`V` 是当帧的实时判决（不是统计值），逐帧对照 `tools/doa_view.py` 的 CSV 第 6 列
（`mot` 列，"01" = v1 开、v2 关）即可。

### 8.7.9 板上实测（2026-10-31 23:18）：v2 判得对，但它切到的那档记忆是错的

带 `V` 字段的第一次上板，同一套圆周测试，两份数据同口径对照
（`sim/sim_v3_check.py`、`sim/sim_seg_cmp.py`、`sim/sim_rate.py`）：

| | 旧固件（只有 v1）`circle_v2.csv` | 新固件（v1∪v2）`circle_v3.csv` |
|---|---|---|
| 连续段 | 0–59.2 s @47.7 Hz | 0–30.7 s @47.8 Hz |
| 能量中位 | 1445 | 1494（同一量级，条件可比） |
| 实际转速 | 22–63 °/s | 28–55 °/s |
| **>30° 跳变** | **12.2 次/分** | **82.1 次/分** |
| 中位 \|Δθ\| | 0.00° | 1.00° |

判据本身是对的：`V=<v1><v2>` 里 v2 在转动段 97–100% 开、静止的 0–5 s 只有 10% 开、
全程 84.7%；把同一份 DOA 序列喂给 RTL 定点重放，与板上上报值只差 0.7%（边界效应）。
也就是说 **v2 该开的时候开了、该关的时候关了**，8.7.4 的设计目标达到了。

问题出在"开了之后把记忆切到哪里"。`SM=3` ⇒ 记忆 8 个快拍，而阵元数正好也是 8：
8 快拍的样本协方差在 8 阵元下**秩亏**，求逆时数值爆炸，MVDR 的空间谱会随机长出
深的伪零点，于是角度成片地 30°~160° 乱跳（典型形态：15.16–15.41 s 六帧内
147→96→149→92→255→43→151）。旧固件里 v1 快转时基本不触发（8.7.1），所以
大多数帧还停在 S=7 的长记忆上，虽然滞后但平稳——12 次/分是"滞后代价"，
82 次/分是"秩亏代价"，后者显然更糟。

排除过的一种解释（`sim/sim_v2_clamp.py`）：单帧大跳变把 m 顶高后锁死 v2
（163° 的跳变会让 m 衰减 0.67 s，饱和时 1.1 s）。实测把喂进 EMA 的增量
限幅到 ±8°/±4° 后，"v2 开但没在动"的帧数一模一样（90 帧 / 6.1%），
说明转动期间 v2 是被真实运动维持的，不是被跳变锁死的。所以没有加限幅。

先量清楚这些跳变到底长什么样（`sim/sim_step_hist.py`）：

| \|Δθ\| 分布 | circle_v3.csv |
|---|---|---|
| 0–2° | 95.5%（中位 **1.00°**，正好是 47.7 Hz × 48°/s 的真实转角） |
| 2–10° | 0.4% |
| 10–30° | 1.2% |
| **≥30°** | **2.9%** |

也就是：**MVDR 每帧的典型精度一点没坏，坏的只有 2.9% 的尾巴**。秩亏不是把
整体估计变糊，而是偶尔把谱峰甩到伪零点上。既然如此，拉长记忆（SM 3→5）等于
拿"所有帧都付出 0.34 s 固定滞后（55°/s 时约 19°）"去换"少一点尾巴"——不划算，
也直接违背"不损失精度"。

**最终改动：SM 保持 3，在输出端剔除单帧离群**（`mvdr_axi_top.v`）：

```
d = wrap(新角 − 上次接受的角)
|d| ≤ GATE_DEG(20°)                                → 立即接受
    （真运动 47.7Hz 下每帧最多 2~4°，20°/帧 = 954°/s，
      人手/转盘够不着 ⇒ 正常帧的输出与未加门时逐位相同）
否则候选连续 GATE_N−1(2) 帧落在 GATE_TOL(10°) 内  → 接受（真跳变延迟 2 帧 = 42 ms）
扣住满 GATE_MAX(8) 帧                              → 强制接受（防卡死，≤168 ms）
其余                                               → 保持上一帧输出
```

参数 `GATE_EN=1 / GATE_DEG=20 / GATE_TOL=10 / GATE_N=3 / GATE_MAX=8`；
`GATE_EN=0` 时与原版逐位一致，方便对照回退。位置在 `S_RUN` 的 `if (warm_ok)` 里，
接受/保持两支都在同一拍给出 `doa_done`，UART 与 DAS 的时序不变；新增只有
`gate_init/gate_pend/gate_cnt/gate_pn` 四个寄存器（9bit×2 + 4bit×2）和几个
比较器，不碰关键路径。

**用真实记录回放的验证**（`sim/sim_gate.py`，直接把 csv 的角度序列过一遍，
不是模型估算）：

| 记录 | 原始 >30° 跳变 | 加 GATE 后 | 保持帧 |
|---|---|---|---|
| circle_v3.csv | 42 次（82.1/分） | **0 次** | 2.1% |
| run.csv | 27 次 | 9 次 | — |
| circle_v2.csv（旧固件，整段 40 min，含大量静止） | 42 次 | 12 次 | 1.0% |
| circle_slow2.csv | 50 次 | 14 次 | — |

circle_v3 上 **97.9% 的帧与未加门时逐位相同**，只有 2.1% 被扣住，且被扣住的
都是单帧孤立尖峰——下一帧回到真值附近就立刻接受。

判据留着的另一个用处：如果这次上板后**轨迹顺滑但整体落后十几度**，那就不是
跳变问题，下一步调 G（PRED 外推倍数）；如果 v2 判动期间仍成片连跳，说明 8 快拍
对 8 阵元真的不够，下一个杠杆是前后向平均——但 UCA 上要用**按 N/2 循环移位**
构造的变换矩阵 J_c（不是线阵的反转矩阵 J），且它作用在 MVDR 谱上的增益要先离线
验证过再上板（理论上 a^H J_c R* J_c a = (a^H R a)*，对完整协方差可能是个恒等变换）。

### 8.7.12 拍手瞬态旁路（CLAP，2026-11-01 已写进 RTL）

限速的副作用是"新声源出现在远处时爬得慢"。拍手是**瞬态**：能量在几个帧内抬高
好几倍；圆周转动时能量虽然也变，但那是秒级慢变。用两档能量 EMA 的比值区分：

```
e_fast ← e_fast − e_fast/4  + pwr     稳态 4×pwr，τ≈4 帧（84 ms）
e_slow ← e_slow − e_slow/64 + pwr     稳态 64×pwr，τ≈64 帧（1.34 s）
事件   = e_slow > 2048 且 e_fast<<5 > 5·e_slow
         ⇔ ef/es > 0.156，而稳态 ef/es = 1/16 = 0.0625 ⇒ 门限 = 稳态值的 2.5 倍
命中 ⇒ evt_cnt = CLAP_HOLD(24 帧≈0.5s)，窗口内限速由 SLEW_DEG(8) 换成 SLEW_EVT_DEG(25)
        （⚠ 8.7.17 已改为 CLAP_HOLD=32、SLEW_EVT_DEG=6，本节保留当时的写法）
```

**2026-11-01 修正：窗口内不是"完全旁路"，而是限速 25°/帧。**
最初写的是完全旁路（显示直接等于 GATE 目标）。上板日志：

```
M=052 E=00000D68
M=140 E=00000D43      ← 一帧跨 88°，用户反馈"拍手响应还是有跳变"
```

### 8.7.14 三种工况能不能同时成立（2026-11-01）

| 工况 | 机制 | 保证程度 |
|---|---|---|
| 定点持续声源 | GATE 剔单帧离群 | 实测中位步进 0~1°，>30° 事件 0~0.4 次/分（8.1/8.2 的多径），**不是 100%** |
| 圆周环绕 | SLEW 构造上 ≤8°/帧 | **100%**，v5 的 7171 个连续观测对里 ≥9° 的有 0 个 |
| 拍手 | CLAP 旁路，显示 1 帧跟到 GATE 目标 | 总延迟 = GATE 3 帧 + 判据 2 帧 ≈ 105 ms |

**定义上的前提**：拍手时那一步跨过去，本身就 >8°。如果"跳变"定义为 >8°/帧，
那么"拍手瞬时响应"与"不跳变"描述的是同一件事，不可能同时满足——能保证的是
**一次到位、之后不再乱动**，不是慢慢滑过去。

剩下三个失败模式（都已量化，不是猜测）：

1. **相干多径错峰**：定点时偶发，0~0.4 次/分，实测未复现（8.2）。会看到一次
   ≤68° 的软移动（SLEW 摊成 ~9 帧）。
2. ~~**圆周中有人拍手**：evt 窗口内限速被旁路，可能一步跳过去~~ **已消除**：
   窗口内限速改为 SLEW_EVT_DEG（现 6°/帧，见 8.7.17），任何情况下单帧都不超过该值。
3. **拍手判据晚 2 帧开窗**：用 circle_v5 的帧 7062 实测（E 75→3748 一步），
   ef/es 从 0.02 → 0.09 → 0.14 → 0.17 才越过 0.156，所以前 2 帧仍按 8°/帧 走。
   这 2 帧正好吃掉 16°，对总响应（≈105 ms）影响可忽略，不需要改门限。

**验证方案**（一次记录同时覆盖三种工况，避免多上板）：静止 30 s → 圆周 60 s →
回到静止拍手 5 次。`sim_gap_check.py` 看圆周段 ≥9° 计数，
`sim_evt_int.py` 看拍手帧是否落在 evt 窗口内。

### 8.7.15 A 档：按"距离"的大跨步（2026-11-01 已写进 RTL）

**问题**：CLAP 靠能量瞬态，拍手有、**搬动一个持续发声的声源没有**。这种换向的
显示段按 8°/帧 走，180° 要 22 帧 = 0.47 s，用户看到的就是"慢吞吞爬过去"。

**规则**（`SLEW_BIG_DEG=25`、`BIG_TRIG_DEG=45`）：

```
显示角与目标的差距 > 45°  →  进入 big_move，本段移动全程 25°/帧（== SLEW_EVT_DEG）
本帧能一步走到目标         →  退出 big_move（避免最后几十度又爬回 8°/帧）
else                       →  8°/帧（圆周正常转动，一帧都不受限）
```

45° 这个门限的依据：真实转动最快 ~90°/s（2°/帧），显示滞后只有几度，差距永远碰不到
45°；能碰到的只有"新声源/换向"这种真跳变。25°/帧 与拍手窗口同档，单帧仍 <30°
（= 用户判"跳变"的门限），所以"不跳变"和"快"两条同时成立。

**验证 1 —— 合成工况**（`sim/sim_big.py --jump`，能量恒定、无拍手瞬态）：

| | 走完 180° | 单帧最大 | >30° 帧 |
|---|---|---|---|
| A 档关 | 24 帧（504 ms） | 8° | 0 |
| A 档开 | 9 帧（**189 ms**） | 25° | 0 |

**验证 2 —— 回放真数据**（`sim/sim_big.py --detail <csv>`，看 A 档在哪触发）：

| 记录 | 输入最大步进 | A 档关 | A 档开 | A 档触发点 |
|---|---|---|---|---|
| circle_v5（当前构建，240 s） | 111° | max 8° | max 25° | 5 次，**全在记录空档**（22.98/2.60/5.21/2.60/1.79 s） |
| circle_v4 | 68° | max 10° | max 25° | 1 次（帧 4274，27°→95° 那次真跳变，V=11） |
| static_v4（静止 75 s） | 8° | max 8° | max 8° | **0 次** |
| clap_log_20261101 | 88° | max 25° | max 25° | 3 帧（原本就走 CLAP 窗口，结果不变） |

结论：**连续录制的圆周、静止，A 档一次都不触发**（触发点全是 PC 记录断流造成的
角度断层），所以 8.7.13/8.7.14 里"圆周不跳"的结论不受影响。

### 8.7.16 大变化后重建协方差（flush → 对角加载，2026-11-01 已写进 RTL）

**问题**：S=7 的 EMA 记忆 128 快拍（1.34 s）。声源一次换了方向后，这 128 个快拍
里全是**已经不存在的方向**，新方向要等旧数据被"挤"出去才占主导——这就是
"换向之后还要再等 0.2~0.7 s 才稳"的来源，也是 circle_v3/v4 里"连续 3~8 帧锁错峰"
的成因（错峰被长记忆锁住，GATE 按设计放行）。

**做法**：`GATE` 接受一次跳变跨过 `CLR_DEG=30` 时拉 `flush_req`，`cov_accum` 在下一个
快拍把 288 项**全部重写成 λ·I**（对角加载），`k` 归零，从"噪声底 + 新快拍"重新开始。

**为什么是加载而不是清零**（`sim/sim_clr_check.py`，8 元 UCA + 8 bin 融合）：

| 重建后新快拍数 | 加载量 λ | R 条件数 | MVDR 峰方向 | 谱对比度 |
|---|---|---|---|---|
| 2 | **0（=清零）** | 2.0e15 | **−96°（真值 137°）** | — |
| 2 | trace/8 | 3.1 | 137° ✓ | +4.1 dB |
| 2 | **trace/16（采用）** | **5.2** | 137° ✓ | +6.1 dB |
| 2 | trace/32 | 9.3 | 137° ✓ | +8.5 dB |
| 8 | **trace/16（采用）** | **17.4** | 137° ✓ | +11.2 dB |
| 稳态（128 快拍，无加载） | — | 1.3e3 | 137° | +28 dB |

清零后 R 只有秩 2（K=2），8 阶逆矩阵不存在，`mat_inv` 输出什么全看噪声——
峰直接甩到错方向。加了 λ·I 后 R 满秩，**第一帧就指对**，代价是谱浅（+6 dB vs 稳态
+28 dB），几帧后随新快拍填入逐渐变尖。10 dB 信噪比下结论相同。
`CLR_LD=4`（λ = 单快拍每 bin 迹 / 16）是"条件数 5~17 / 对比度 6~11 dB"的折中点。

**实现要点**：

- 288 拍（5.8 µs）改写 + 丢弃当前快拍，只在"大变化被确认"时发生一次。
- 写地址和写数据必须**同拍寄存**（MAC 路径的 `m_re_d` 就是干这个的）。第一版忘了，
  数据会比地址早一项 → 对角加载错位。`sim/sim_clr_seq.py` 逐拍复现写端口语义，
  发现并确认了修复：289 拍、288 次写、地址 0..287 全覆盖、λ 只落在 64 个对角位置
  （每 bin 的 0/8/15/21/26/30/33/35）、224 个 0、无一项被写成 EMA 结果。
- `pwr_acc`（迹 EMA）不动，所以 0x34 PWR 和拍手判据不受影响；稳态 R 里加载只占
  ~2% 并随 EMA 继续衰减。

**时延账**（180° 换向，一次记录里能看到的）：

| 段 | 旧 | 新 |
|---|---|---|
| 估计器拐过来（动检 v1/v2 命中后 SM=3 短记忆） | 84~170 ms | 84~170 ms（不变） |
| 拐过来之后被长记忆往回拽 / 锁错峰 | 200~700 ms | **≈0**（已重建） |
| GATE 确认 | 63 ms | 63 ms |
| 显示走完 180° | 470 ms | **150 ms**（A 档） |
| **合计** | **≈0.8~1.4 s** | **≈0.3~0.4 s** |

⚠ 仍未上板。上板要看的：换向时重建那一下有没有可见的"停一拍"（丢一个快拍，
21 ms，应该在 GATE 的确认窗口里看不出来）；以及重建后头几帧角度抖动会不会被
GATE 扣住（谱浅 ⇒ 峰宽 ⇒ 抖动可能到 ±5~10°）。

### 8.7.17 拍手不再提速：瞬态窗口"禁止大跨步" + 6°/帧（2026-11-02 已写进 RTL）

**用户反馈**：25°/帧 时拍手仍然"太跳变，真的不好"。要求只改拍手，圆周与定点不许动。

**根因**：8.7.12 的 25°/帧 只是把 88° 从"1 帧"摊成"3 帧"。人眼在 30 fps 的界面上
看到的是指针在 ~2 个画面内瞬移，依然是"跳"，不是"扫过去"。所以拍手路径上任何
"提速"都解决不了观感——只能匀速扫，而且要比普通转动更慢（8°/帧 → 6°/帧）。

**改动（`mvdr_axi_top.v` 三处参数/条件，逻辑没动）**：

```verilog
parameter CLAP_HOLD    = 32;     // 原 24；窗口 0.67 s，足够走完 32×6=192°
parameter SLEW_EVT_DEG = 6;      // 原 25；比 SLEW_DEG(8) 还低一档 ⇒ 瞬态窗口内更慢
wire accept_big = accept_any && (slew_ad > BIG_TRIG_DEG) && (evt_cnt == 5'd0);
                                 // 新增 evt_cnt==0：能量瞬态期间不进 A 档
```

第二条是关键：只把 `SLEW_EVT_DEG` 改小没用——GATE 一接受那个 88° 目标，
`accept_big`（>45°）立刻把 `big_move` 置位，限速又回到 25°/帧。加上 `evt_cnt==0`
之后，拍手全程走 6°/帧；"搬动持续声源"没有能量突变、`evt_cnt` 恒 0，A 档照旧。

**回放验证**（`sim/sim_clap_smooth.py`，与 RTL 逐位同逻辑，含 GATE/CLAP/big_move）：

| 记录 | 现状 A（25°/帧） | 改后 B（6°/帧） |
|---|---|---|

拍手逐帧对照（同一份 clap_log，原始 52 → 140）：A 是 `52→77→102→127→141`，
B 是 `52→58→64→70→76→82→88→94→100→106→112→118→124→130→136→140`。

**代价（要写进报告的）**：拍手响应从"63 ms 到位"变成"**336 ms 到位**"
（GATE 扣住 2 帧 = 42 ms + 14 步 × 6°/帧 = 294 ms）。这是用户明确选择的取舍：
"瞬态响应快"与"不跳变"在显示端是同一件事的两面（8.7.14 已写明），
既然判"跳"，就只能放慢。6°/帧 是单帧 6° 的硬上限——只要窗口内不走 A 档，
指针在 30 fps 界面上每一步都 ≤6°，不会再出现瞬移。若仍嫌慢，把
`SLEW_EVT_DEG` 调回 8（≈252 ms）即可，其余逻辑不用动。

**副作用（好的）**：拍手判据误触发（说话、关门等）不再造成任何加速，
窗口现在只会"冻结 A 档 32 帧（≈0.67 s）"，最坏情况是那一次搬移慢一点。

### 8.7.18 拍手窗口内"只信峰值附近"：堵住 GATE 的两个口子（2026-11-03 已写进 RTL）

**用户澄清**：8.7.17 改的是"指针怎么走过去"，落点没变。用户说的是**同一次拍手，
输出角本身在动**（"我在某个方位拍一下手，它输出的角度本身就大幅度不一样"）。
SLEW 对这件事无效，必须从估计端/接受端下手。

**先看已有的那份 clap_log（唯一一次拍到手的记录）**：

```
原始角 52 52 140 140 141 142 141 141 141 141 ... 140 140 139 137 137 144 144 143 143 147 145 144
pwr    3352 3432 3395 3355 ... 2427 2074 1588 1316 1216 931 712 600 415 244 187 143 109 84
```

- 前 0.5 s（pwr > 2400，峰值的 −1 dB 以内）：140–142，**±1°**，非常稳；
- 0.5 s 之后能量从峰值掉 6–12 dB：角开始走到 139→137→144→147（±7°）；
- 尾巴最后几帧 pwr 只剩峰的 **1/40**，R 里已经没有信号，估计器纯靠噪声给角。

所以"拍手时角自己在动"，能看到的部分就是**衰减尾巴被当成有效估计收下了**。代码里有
两个口子，都只影响事件窗口：

1. `gate_pass`：偏离目标 ≤ `GATE_DEG`(20°) 的帧**立即接受**——噪声在 ±20° 内随便走；
2. `gate_force`：扣满 `GATE_MAX`(8 帧) **强制接受**——噪声只要稳定偏 20°~40° 以上，
   168 ms 后照样收下（拍手尾巴正好这么长）。

**改动（只作用在 `evt_cnt != 0` 的 32 帧里，圆周/定点路径逐位不变）**：

```verilog
parameter integer SIG_EN    = 1;   // 1 = 开；0 = 关（回到 8.7.17 的行为）
parameter integer SIG_DB_SH = 1;   // 峰值下降 2^SIG_DB_SH 倍后不再更新（1 = 6 dB）

wire gate_force = ((gate_cnt + 4'd1) >= GATE_MAX) && (evt_cnt == 5'd0);   // 窗口内不放行
wire [31:0] peak_now = (pwr_reg > pwr_peak) ? pwr_reg : pwr_peak;         // 事件峰值（运行最大）
wire        sig_ok   = (SIG_EN == 0) || (evt_cnt == 5'd0) ||
                       (pwr_reg > (peak_now >> SIG_DB_SH));
wire        accept_g = accept_any && sig_ok;        // 真正落到 doa_tgt 的接受
```

`pwr_peak` 在事件窗口内跟踪最大值（信号可能比判据晚 1 帧到）。**只用相对峰值，
不用绝对门**：static_v4 的 pwr 中位只有 1243，比拍手判据的 2048 还低，绝对门会把
正常定点声源也挡掉。

**核对时发现并修掉的一个隐患（差点上板才发现）**：`gate_force` 在窗口内关掉后，
`gate_cnt` 会一直涨到 4bit 上限。原写法 `gate_cnt + 4'd1` 到 16 回绕成 0：

- 把"候选自洽"计数清零，白等几帧；
- 更糟的是 `(15+1) = 0 >= GATE_MAX` **恒假** ⇒ 窗口结束后"扣满 8 帧强制放行"
  永久失效，8.7 当初防卡死的保险丝被熔掉。

改为饱和在 `GATE_MAX-1`（=7）：窗口内停在 7，窗口一结束下一帧就能触发强制放行。

```verilog
gate_cnt <= (gate_cnt >= (GATE_MAX - 1)) ? gate_cnt : (gate_cnt + 4'd1);
```

**核对手段**（这台机器上 Vivado 没挂载，**没有跑语法检查**）：

- 逐行人工核对：声明顺序（`pwr_reg` 从下方移位到 reg 区、无重复声明）、单驱动、
  复位覆盖（`pwr_peak` 已加复位）、位宽（4bit 计数器 / 32bit 能量 / 44bit EMA）；
- 新增 `sim/param_check.py`：从 RTL 抠出全部参数，与回放模型的常量逐项比对，
  并检查 evt 判据的三个写死常数（2048、`>>2`、`>>6`、`<<5`/`<<2`）——全部一致；
- 回放模型同步了 RTL 的 4bit 语义（`gate_cnt` 饱和、`gate_pn` 回绕），
  饱和修复后重跑四份记录，结论与上面那张表逐位相同。

**回放验证**（`sim/sim_clap_smooth.py` 三个版本：A=旧 25°、B=6°、C=6°+峰值门）：

| 记录 | A / C 输出不同帧 |
|---|---|
| static_v4 | **0 / 1144**（逐位相同） |
| circle_v5 | 28 / 7178（0.4%，帧 7066–7085 记录空档内） |
| circle_fast | 19 / 1991（1.0%，帧 32–37 声源刚打开的爬升段） |
| circle_slow2 | 52 / 6666（0.8%，都在记录空档） |

clap_log 上：C 在帧 34–35 保持 144，B 已飘到 147/145。**这份记录的尾巴本来只飘 ±7°，
所以改善看着不大——C 的价值在于把"±20° 内立即接受 + 8 帧强制接受"这两个口子关掉，
真实板上尾巴飘得更大时才会显出差别。**

**这一条解决不了的事（必须说清）**：如果**不同次拍手**（同一方位）的最强帧估计本身
就差几十度，那是单帧估计的方差——拍手 ~1 ms，FFT 窗 10.7 ms，一次拍手可能落在一帧里
也可能跨两帧劈开，8 个 bin 里哪几个有能量每次不同。任何显示端门限都救不了，只能换
估计方法（拍手专用的一次性互相关/SRP）或加长分析窗，那是另一个量级的改动。
**判断方法是：同一方位连续拍 5 下，看 5 次最强帧的角度。**
