## 一、需求（用户 2026-10-22 提）

1. **实时频谱**：PC 界面上一条随声音高低跳动的频谱。
2. **8 方位频谱**：极坐标雷达图的 8 个方位角上各挂一条频谱，声源方向那条最高，测试时一眼看出哪个方向声音最大。
3. **识别用频谱**：声源识别 / 声纹识别各自显示输入音频的频谱（语谱图），不同声源频谱形状不同。
4. 同时显示：极坐标 DOA、类别、说话人编号、置信度。

## 二、总体架构

显示**全部放 PC**，PL 只负责把两路数据流送出去，PS 只做「搬运 + 8 方位波束计算 + 组包转发」。

```
PL (50MHz)                                   PS (ARM / Linux)              PC
──────────────────────────────────────       ───────────────────────       ──────────────
8 路 FFT 频谱 (64bit×8ch×512bin) ─┐                                          ┌ 单麦实时频谱
                                  ├─▶ 异步FIFO(50→100M) ─▶ AXI DMA #1 ─▶ DDR ┤
波束音频 16bit@48.828k ───────────┤                                     │    ├ 8 方位频谱
                                  └─▶ 异步FIFO(50→100M) ─▶ AXI DMA #2 ─▶ DDR ┤
AXI4-Lite 寄存器 ◀── AXI Interconnect ◀── M_AXI_GP0                        │    ├ 语谱图
                                                    PS 计算 8 方位波束谱 ───┤    ├ 极坐标 DOA
                                                    组包 → TCP/UDP ────────┴──▶ └ 类别/声纹
                                                                  网口(千兆)
```

**两路 DMA 是必须的**：AXI DMA 只有一个 S2MM 通道，频谱流和音频流要各占一路。

## 三、关键结论：不能用 8 个麦克风的频谱当 8 个方位

⚠️ **这是最容易做错的地方。**

麦克风是全向的。同一个声音到达 8 个麦时，幅度几乎一样（只差 5 cm 半径带来的几 dB），**方向信息全部在相位里**。所以把 ch0~ch7 的幅度谱摆在 8 个方位上，会得到 8 条几乎重合的曲线，完全看不出方向。

必须做**波束成形**把相位差转成幅度差：

```
B(θ, f) = | Σ_i  X_i(f) · e^(+j·kR·cos(θ−α_i)) |²
```

- `X_i(f)`：第 i 个麦克风在频率 f 的复数谱
- `α_i = i×45°`：麦克风物理角度
- `kR = 2πfR/c`，R = 0.05 m，c = 343 m/s
- θ 取 0/45/90/…/315 八个方向

θ 对准声源时 8 路同相相加 → 幅度平方放大 64 倍；θ 背对时相互抵消 → 接近 0。这样才看得出「哪个方位声音最大」。

### 计算量与放置位置

| 项目 | 数值 |
|---|---|
| 每帧计算量 | 8 方向 × 128 bin × 8 通道 = 8192 次复数乘加 |
| 刷新率 | 95.4 Hz（见第六节），实际按 30 fps 限速显示 |
| 每秒计算量 | ~78 万次复数乘加（按 95.4 Hz）；限速 30 fps 后 ~25 万次 |

**放 PS 算（2026-10-22 定案，用户指定）**，算完只传 `8 × 64 = 512` 字节/帧，带宽可忽略，PC 端不需要知道任何阵列参数。

### 为什么放 PS 而不是 PL / PC

| 方案 | 优势 | 代价 |
|---|---|---|
| PL 算 | 不占 CPU | 要多写 8 路并发波束乘加，占 LUT/DSP，且这是纯显示用途，不值得挤时序余量 |
| **PS 算（选定）** | **软硬件协同**：PL 做实时硬约束处理（FFT/协方差/求逆/扫角/波束成形），ARM 做显示后处理；不占 PL 资源；C 端只画图 | 占一点 A9 算力（实测预算 <5% 单核） |
| PC 算 | 调试最快 | 要传 3.1 MB/s 原始复数谱，且 PC 端要自己懂阵列几何 |

选 PS 的核心理由：**让 ZYNQ 的 PL 和 PS 两端都承担实质运算**，而不是把 ARM 只当搬运工。答辩时若被问「为什么不用 PC 算」，答案就是：阵列后处理放在 ARM 上，PC 只做可视化，系统更接近嵌入式一体机的形态，且上行带宽降到 1/6。

> ⚠️ 注意措辞：**放 PS 算不会提高 PL 的资源利用率**（PL 仍是 54.8%），提高的是「整板（PS+PL）参与度」。若目标是 PL 数字好看，反而应该搬回 PL。

### 算力预算（给 B 参考）

| 项目 | 数值 |
|---|---|
| 每帧复数乘加 | 8 方向 × 128 bin × 8 通道 = 8192 |
| 每帧实数运算 | ≈ 6 万次（含加减） |
| 帧率 | 95.4 Hz（可限速 30 fps，省 2/3） |
| 每秒运算 | 约 570 万次浮点运算 |
| A9 @667 MHz 占用 | **< 5%（单核）**，限速 30 fps 后 <2% |

**关键优化**：导向表只跟 bin 序号和方向有关，与数据无关 → **启动时预计算一次**（8×128×8 个复数 = 64 KB），每帧只做表驱动乘加，不调用 `cosf/sinf`。

### 3.1 与 DOA 测向的关系（两者互不影响）

| | 谁算 | 分辨率 | 用途 |
|---|---|---|---|
| DOA 测向 | PL 的 `mvdr_sweep` | **1°**，全 360° | 极坐标指针位置、`DOA=+37°` |
| 8 方位频谱 | PS 现算 | **45° 一档** | 仅可视化 |

- 8 方位谱**不参与**测向，DOA 精度仍是 1°；不显示 8 方位谱时测向照样工作。
- 8 只是**显示粒度**，可随时改 16 / 36 方位（计算量见下表），界面挤不下时别加太多。

| 方位数 | 每帧复数乘加 | 视觉感受 |
|---|---|---|
| 8（45°） | 8192 | 够直观，柱条不挤 |
| 16（22.5°） | 16384 | 更细腻 |
| 36（10°） | 36864 | 接近连续扇贝环，屏幕易糊 |

### 3.2 ⚠️ 角度映射：物理角 = 显示角 + 180°

汇报的 `doa_deg` 做过 **+180° 安装偏移**（ch0 物理装在板子最左）。因此算方位谱时必须反解：

```
B(θ_显示, f) = | Σ_i  X_i(f) · exp( +j·kR·cos(θ_显示 + 180° − α_i) ) |²
```

- `α_i = i×45°` 是麦克风的**物理**角度
- 漏掉这个 +180°，整圈频谱会**正好反 180°**（声源在右、最活跃的谱却在左）
- 这与 `bf_audio_out.v` 里的反解是**同一个坑**：`doa≥0 → r=doa/2`，`doa<0 → r=(doa+360)/2`（表内角度 = 汇报角度 − 180°）
- 建议：先用单频 4.1 kHz 纯音在 0°/90°/180°/270° 四个位置各测一次，确认四个方位谱的峰值都跟着走，再上复杂声源

## 四、频率轴与分辨率取舍

### 4.1 现状参数

| 参数 | 值 |
|---|---|
| 采样率 | 48.828 kHz（50 MHz ÷ 16 ÷ 64，整数分频） |
| FFT 点数 | 512 |
| 频率分辨率 | 48828.125 / 512 = **95.367 Hz/bin** |
| 单通道帧周期 | 10.49 ms（95.4 fps） |

### 4.2 与参考作品（MES50HP，HDMI 方案）的对比 —— 写进报告的论述

参考作品采用 16 kHz 采样 + 256 点 FFT，分辨率 62.5 Hz。我们的分辨率 95.4 Hz 略低，**但这个对比不是「谁更好」，而是取舍不同**：

- **我们的采样率不能降到 16 kHz**。48.828 kHz 是由 I2S 位时钟整数分频得到的，且**所有导向表（steer_*.mem）和 DAS 延时表都按 48.828 kHz 生成**，改采样率 = 重做整个测向链。
- 测向需要 4 kHz 以上的频段做 8 bin 融合（最高 bin43 = 4100.8 Hz），16 kHz 采样（Nyquist 8 kHz）虽然够，但采样率一变，kR 全变。
- **显示时只画 0~8 kHz 对应的 bin 0~83**（84 根柱子），视觉密度等价于「16 kHz 采样」的观感，完全够用。
- 若要 62.5 Hz 分辨率需改 1024 点 FFT，会翻倍资源，**不值得**。

> 报告里可直接引用这段：说明我们评估过采样率/点数/分辨率/资源四者的权衡，并给出选择理由。

### 4.3 显示用 bin 范围

| 用途 | bin 范围 | 频段 | 柱子数 |
|---|---|---|---|
| 单麦实时频谱 | 0~83 | 0~7.9 kHz | 84 |
| 8 方位频谱 | 0~63 | 0~6.1 kHz | 64（可再压缩） |
| 语谱图 | 0~127 | 0~12.2 kHz | 128 × 时间 |

## 五、数据格式

### 5.1 PL → PS：频谱流（`fft_axis_*`）

| 信号 | 方向 | 位宽 | 说明 |
|---|---|---|---|
| `fft_axis_tdata` | PL→DMA | 64 | `{imag[31:0], real[31:0]}`，real 在低 32 位 |
| `fft_axis_tvalid` | PL→DMA | 1 | 数据有效 |
| `fft_axis_tlast` | PL→DMA | 1 | 每路第 512 点（帧末）拉高 |
| `fft_axis_tready` | DMA→PL | 1 | 背压 |

- **8 路 × 512 bin 分时**，数满 8 次 `tlast` = 一轮完整 8 路谱
- 一轮 = 4096 字 = **32 KB**，**每 10.49 ms 出一轮**
- 带宽 = 32 KB / 10.49 ms ≈ **3.1 MB/s**（平均）

> 为什么是 10.49 ms 而不是 8 × 10.49 ms：`i2s_fft8_axis` 是**乒乓缓冲**，8 个通道的 512 点在同一 10.49 ms 窗口内同时写满，然后一次性把 8 帧连续灌进 FFT 核（读空一轮只要 ~82 µs，源码注释写 41 µs）。所以 8 路谱来自**同一时刻**，一轮 = 一个采样帧周期。
>
> 实际输出是**突发式**的：每 10.49 ms 里集中 82 µs 吐完 32 KB，其余时间空闲。平均 3.1 MB/s，突发瞬时速率约 390 MB/s（受 AXI 时钟限制）。DMA 和 FIFO 必须能吃住这个突发——**FIFO 深度要按 32 KB 突发来估**，不能按平均值估。

### 5.2 PL → PS：波束音频（`m_axis_audio_*`）

| 项目 | 值 |
|---|---|
| 格式 | 有符号 16 bit 单声道 PCM |
| 采样率 | 48.828 kHz |
| 帧边界 | `tlast` 每 1024 样本 = 21.0 ms |
| 带宽 | 97.7 kB/s |

### 5.3 PS → PC：建议包格式

```c
struct pkt {
    uint32_t magic;      // 0x52534452 "RSDR"
    uint16_t seq;        // 帧序号，PC 用来丢帧检测
    uint8_t  type;       // 1=频谱 2=音频 3=结果
    uint8_t  len;        // 负载长度
    int16_t  doa;        // 当前 DOA，有符号度
    uint8_t  cls;        // 类别编号
    uint8_t  spk;        // 说话人编号
    uint8_t  conf;       // 置信度 ×100
    uint8_t  reserve;
    uint8_t  payload[];  // 8 方位谱: 8×64 = 512 B
};
```

建议 **UDP**（PC 端丢一帧无所谓，比 TCP 简单、无阻塞风险）；若要传音频回放则用 TCP。

1. **把 4 个频谱端口加回 `radar_pl_top_bd.v`**（当前没有，只有 `s_axi_*` + `m_axis_audio_*`）：

## 八、PS / PC 侧分工

**队友 B（PS）**
1. 两路 AXI DMA + 两个异步 FIFO（50→100 MHz）
2. DMA 收到的 8 路复数谱 → **算 8 方位波束谱**（算法见 8.1，2026-10-22 定案放 PS）
3. 组包（第五节格式）→ UDP 发 PC
4. CNN 分类 + 声纹嵌入（吃波束音频）→ 结果一并打包

**队友 C（PC）**
1. UDP 收包 → 解析
2. 8 方位频谱挂在极坐标雷达图各方位（**C 不做任何阵列运算，纯绘图**）
3. 语谱图滚动显示
4. DOA 指针 / 类别 / 说话人 / 置信度
5. **离线回放模式**（见第十节）

### 8.1 PS 侧波束谱算法（B 照抄）

**第 1 步：解析 DMA 数据**

一个字 64 bit，`{imag[31:0], real[31:0]}`，**有效精度 24 bit**（高位符号扩展）：

```c
int32_t re = (int32_t)word[31:8];   /* 有符号，24bit 左移 8 位后的值 */
int32_t im = (int32_t)word[63:40];
```

一轮 4096 字 = ch0.bin0..511 → ch1.bin0..511 → … → ch7.bin0..511。
**判帧边界用 `tlast`**（DMA 的 `TLAST` 标志），数满 8 个 tlast 才算一轮完整。

**第 2 步：启动时预计算导向表（只做一次）**

```c
#define NDIR   8        /* 8 个方位，45° 一档 */
#define NBIN   128      /* 只用 0~12.2 kHz */
#define R_M    0.05f    /* 圆阵半径 50mm */
#define C_SND  343.0f
#define FS     48828.125f

static float sr[NDIR][NBIN][8], si[NDIR][NBIN][8];   /* 64 KB */

void init_steer(void) {
  for (int d = 0; d < NDIR; d++)
    for (int f = 0; f < NBIN; f++) {
      float kR = 2.0f*(float)M_PI*(f*FS/512.0f)*R_M/C_SND;
      for (int i = 0; i < 8; i++) {
        /* ⚠️ 显示角 → 物理角要 +180°（ch0 装在板子最左） */
        float phi = kR * cosf(deg2rad(d*45.0f + 180.0f) - deg2rad(i*45.0f));
        sr[d][f][i] = cosf(phi);
        si[d][f][i] = sinf(phi);
      }
    }
}
```

**第 3 步：每帧计算**

```c
for (int d = 0; d < NDIR; d++)
  for (int f = 0; f < NBIN; f++) {
    float ar = 0, ai = 0;
    for (int i = 0; i < 8; i++) {
      float xr = X_re[i][f], xi = X_im[i][f];
      ar += xr*sr[d][f][i] - xi*si[d][f][i];
      ai += xr*si[d][f][i] + xi*sr[d][f][i];
    }
    P[d][f] = ar*ar + ai*ai;          /* |Σ X·e^{+jφ}|² */
  }
```

**第 4 步：定标成 0~255**

```c
/* 按整帧最大值归一，取 dB 后映射，PC 端直接当亮度/柱高用 */
float mx = 0;
for (...) if (P[d][f] > mx) mx = P[d][f];
uint8_t val = (mx > 0) ? (uint8_t)(255 * log10f(1 + 99*P[d][f]/mx) / 2) : 0;
```

### 8.2 自校验（**必须做**，不用任何仪器）

PL 已经给出 1° 精度的 DOA（寄存器 0x08）。算完 8 方位谱后做一次交叉验证：

```c
/* 每个方位把整段频谱能量加起来，最大值应在声源方向 */
float e[NDIR]; for (d) e[d] = Σ_f P[d][f];
int d_best = argmax(e);            /* → d_best*45° */
```

| 现象 | 说明 | 修法 |
|---|---|---|
| `d_best*45°` 与 DOA 相差 ≤45° | ✅ 正确 | — |
| 正好差 **180°** | 角度映射漏了 +180° | 检查 `d*45+180` 那一项 |
| 差得乱七八糟、和 DOA 无关 | 导向符号反了，或 Q 格式解析错 | 先把 `cosf/sinf` 的符号取反试一次；再检查 `word[31:8]` 的提取 |
| 8 个方位能量几乎相等 | 数据没对齐（帧边界错位，8 个通道混在一起） | 用 tlast 判帧，别用固定长度 |

**验证顺序**：4.1 kHz 纯音 → 在 0° / 90° / 180° / 270° 四个位置各放一次 → 每次都看 `d_best` 是否跟着转。这一步过了，再上说话和拍手。

## 九、网线选型（用户 2026-10-22 要求）

### 9.1 结论

| 情况 | 买什么 | 参考价 |
|---|---|---|
| 笔记本**有 RJ45 网口** | **Cat5e（超五类）或 Cat6 网线，1~2 m** | 5~10 元 |
| 笔记本**没有网口** | **USB 转 RJ45 千兆网卡**（优先 RTL8153 芯片）+ 网线 | 30~60 元 |

### 9.2 选型要点

- **必须 Cat5e 及以上，不能用 Cat5（五类）**。板载 RTL8211E 是**千兆** PHY，千兆要求 8 芯全接；老式 Cat5 很多只有 4 芯，跑千兆会自动降到百兆甚至不通。Cat5e / Cat6 都支持千兆。
- **长度 1~2 m 就够**。板子和笔记本挨着放，长线反而增加衰减和干扰。
- **UTP（非屏蔽）够用**。桌面短距离无强干扰；比赛现场如果旁边有强电设备可选 STP（屏蔽），但不是必需。
- **普通直通线即可，不需要交叉线**。千兆 PHY 自带 Auto-MDIX，会自动翻转收发。
- **买两根**。比赛现场线材损坏是常见故障，多一根备用成本很低。
- **不要买成电话线（RJ11）**。RJ11 只有 4 芯、水晶头更窄，插不进 RJ45 口。

### 9.3 USB 网卡怎么选（笔记本无网口时）

| 芯片 | 评价 |
|---|---|
| **RTL8153** | ✅ 推荐。Linux 内核自带 `r8152` 驱动，Petalinux/Ubuntu 免驱，Windows 10/11 免驱 |
| AX88179 | ⚠️ 能用，但部分 Petalinux 内核版本缺 `ax88179_178a` 驱动，要自己编译 |
| 杂牌无标 | ❌ 避免，驱动来源不明 |

### 9.4 带宽核算（为什么千兆甚至百兆都够）

| 数据流 | 带宽 | 百兆口(12.5 MB/s) | 千兆口(125 MB/s) |
|---|---|---|---|
| 频谱流（平均） | 3.1 MB/s | 25% | 2.5% |
| 频谱流（突发瞬时） | ~390 MB/s（持续 82 µs） | 由 FIFO 吸收 | 由 FIFO 吸收 |
| 波束音频 | 0.098 MB/s | 0.8% | 0.08% |
| 8 方位谱 + 结果 | 0.006 MB/s | 可忽略 | 可忽略 |

**百兆链路都够用**，买 Cat5e/Cat6 只是因为它支持千兆、在未来加音频回放时不必换线，不是因为有带宽压力。

### 9.5 直连的网络配置（必踩的坑）

板子与笔记本**直连时没有 DHCP 服务器**，两边都要手动配同网段静态 IP：

| 设备 | IP | 掩码 | 网关 |
|---|---|---|---|
| 笔记本 | 192.168.1.10 | 255.255.255.0 | 空 |
| 板子（Petalinux） | 192.168.1.20 | 255.255.255.0 | 空 |

- 板子侧：`ifconfig eth0 192.168.1.20 netmask 255.255.255.0 up`
- 笔记本侧：网络适配器 → IPv4 属性 → 使用下面的 IP 地址
- **ping 不通先查两件事**：① 笔记本防火墙挡了 ICMP（Windows 默认允许，但第三方杀软常拦）；② 两边网段不一致
- Petalinux 设备树里必须有 `gem0` 节点，否则 `eth0` 根本不出现

## 十、风险与兜底

| 风险 | 影响 | 兜底 |
|---|---|---|
| 网线/网口故障 | 现场看不到任何频谱 | **PC 端离线回放模式**：用预录数据循环播放，界面照常动 |
| PS 端 8 方位计算跟不上 | 频谱卡顿 | 降采样到 32 bin、或降到 8 方向 × 32 bin |
| 频谱流与 MVDR 共用 tready，DMA 停顿 | 测向也跟着暂停 | BD 里换 Broadcaster 做独立 tready |
| 频谱突发（32 KB / 82 µs）冲垮 FIFO | 丢帧、谱错位 | FIFO 深度按 **32 KB 突发**估，不能按平均值估；或让 DMA 用 Scatter-Gather 大块搬运 |

**建议**：PC 端从一开始就留 `--replay <file>` 开关，把收到的包录成文件，回放时原样播放。成本很低，比赛现场能救命。
